# 角色创建功能使用指南

> **现状（2026-09-25）**：选角与创角已由**水墨（Ink）页面**承载。本文件下方描述的
> `IntegratedCharacterCreationUI` 等旧 Flax GUI 面板栈已停用——
> `CharacterSceneController.TryCreateUI()` 在 `MainUIManager.UseInkCharacterFlow == true` 时直接返回，不再构建任何旧面板。
> 确认新流程无回归后，可整体删除本目录下的旧 UI 文件与此段历史说明。
>
> **门派规则**：创角**不再选择门派**，创建请求恒以 `Profession.None` 发送；
> 服务端 `UserCharacterManagerGrain.SetDefaultStartingLocation` 的 `default` 分支把无门派角色落到 MapId 1000。
> 门派只在角色进入游戏、自行创建或加入门派之后，才在选角行囊与角色面板上显示。

## 水墨创角流程（当前生效）

页面位于 `Game/UI/Ink/Pages/CharacterCreation/`，按 dom-id 由 `InkPageRouter` 串联：

| dom-id | 页面类 | 参考图 | 内容 |
| --- | --- | --- | --- |
| `cc-role-list` | `CcRoleListPage` | — | 登录后首屏：行囊列表 / 进入游戏 / 创建 / 删除 / 退出登录 |
| `cc-gender` | `CcGenderPage` | 图片/6、7 | 水墨笔触双档「男 / 女」+ 右侧全身预览 |
| `cc-face-preset` | `CcFacePresetPage` | 图片/2、3 | 风雅 / 写实分类 + 竖版水墨卡 + 朱红印章 |
| `cc-face-sculpt` | `CcFaceSculptPage` | 图片/4、5 | 捏脸 / 智能捏脸页签 + 横版预设卡 + 更多面容 + 右侧功能列 |
| `cc-name` | `CcNamePage` | — | 命名（无门派）→ 发起创建 |

公共部分：

- `CcStagePage` — 雾白舞台：背景、右侧 `CharacterPreview3D`、右下「Space 下一步」鎏金确认块、左下返回与 ID 水印
- `CcControls.cs` — 笔触双档、键帽提示、水墨卡、标签行、图标入口、确认块、水印等控件
- `CcSession.Current` — 跨步骤状态（性别 / 分类 / 面容索引 / 衣装索引 / 姓名）。
  **页面每次导航都会新建并销毁旧页，跨步骤数据必须放这里，不能放页内字段。**

### 快捷键（页面上画出的键帽都是可按的）

| 键 | 作用 | 生效页 |
| --- | --- | --- |
| `Space` | 下一步 / 进入游戏 / 踏入江湖 | 全部（命名页除外——空格属于名字） |
| `Q` / `E` | 切「捏脸 / 智能捏脸」；在面容页等价于翻分类 | 捏脸、面容 |
| `Z` / `C` | 切「风雅 / 写实」 | 捏脸、面容 |
| `N` | 创建角色 | 角色选择 |
| `V` | 导入捏脸（仅入口，捏脸码格式未定义） | 捏脸 |

实现见 `CcStagePage.HandleShortcuts()` 的各页覆写与 `CcTabRow.SelectTab`。
`Esc` 与右上角「«」、左下「返回」等价。删除角色没标键帽：仓库里找不到可核验的 `KeyboardKeys.Delete` 用法，
宁可不标也不画一个不响应的键帽。

### 选角页的两道防护

- **删除需二次确认**：点一次「删除」只是上膛（提示变朱红「再点一次删除「某某」」），4 秒内再点一次才真的发
  `DeleteCharacterAsync`；切换选中角色或列表刷新都会立即解除。角色删除不可恢复，不该一次点击就生效。
- **满员挡在入口**：服务端 `MAX_CHARACTER_COUNT = 5`（客户端常量 `CcRoleListPage.MaxRoles`）。
  满 5 个时「创建角色」灰化为「角色已满 5/5」，按 `N` 或点击只提示上限，不会让玩家白走四步到命名页才被拒。

### 取景（立绘远近）

- 性别页与命名页用**全身**取景（参考图 图片/6、7.png）。
- 面容预设页与捏脸页用**头肩特写**：`PreviewFramingScale = 0.55`、`PreviewFramingHeight = 0.78`
  （参考图 图片/2-5.png 里立绘都是胸部以上）。
- 这两个值来自 `CharacterPreview3D` 新增的 `FramingScale` / `FramingHeightFrac`，
  **默认 1 / 0.5 与原自动取景公式逐项相等**，所以角色面板、属性 V2 页的取景不受影响。

### 衣装列与色板

- 捏脸页最右一列竖排缩略（参考图 图片/5.png 右侧）选择衣装，下标写入 `AppearanceInfo.Clothing`。
- 捏脸页左下三行圆形色板：发色 / 瞳色 / 肤色，分别写入 `AppearanceInfo.HairColor / EyeColor / SkinColor`。
  这四个字段在旧创建流程里**全部恒传 0**，等于从未带值；现在由玩家选择驱动，
  且都是协议里已有的 int 字段，**不需要改服务端或重新部署 Silo**。
- 控件是 `CcSwatchRow`（选中项带鎏金描边），色值定义在 `CcFacePresets` 的三张表里。

### 关于「智能捏脸」与「导入捏脸」

两者都保留在页面上（参考图 图片/4.png 顶部就有），但当前只有入口：
「智能捏脸」需要图像/算法后端；「导入捏脸」需要捏脸码格式（燕云确有该功能，本项目尚无对应数据结构）。
按 `V` 或点它会记一条日志，不做假反应。

入口与时序：

- 登录成功 → `SceneType.CharacterSelection` → `MainUIManager.OnSceneChanged` 以 `cc-role-list` 为首页初始化水墨 UI
  （`InitializeInkWashUI(initialPageDomId)` 现可指定首页，避免先建战斗 HUD 再跳走的闪帧）
- 创角与选角同处 `Content/Maps/Character.scene`，而 `UIStateManager.TransitionToScene` 对
  「目标场景与当前场景相同」是**直接跳过**的，所以创建回执后由 `MainUIManager.OnCcCharacterCreated`
  显式切回 `cc-role-list`，否则玩家会停在命名页不动

已知资源缺口：`Content/` 下只有一具通用身体模型（`Content/Character/Models/skm_uefn_mannequin.flax`），
没有独立的男/女身体、发型、服饰网格，也没有面容缩略图。因此卡面以书法字占位
（`CcPresetCard.Thumbnail` 为贴图接入点），切换性别暂不改变预览模型
（接入点见 `CcGenderPage` 构造内的注释）。

## 功能概述

集成的角色创建系统结合了基础信息输入和MetaHuman外观编辑器，为玩家提供完整的角色定制体验。

## 核心组件

### 1. IntegratedCharacterCreationUI
**位置**: `Game/UI/Character/IntegratedCharacterCreationUI.cs`

**功能**:
- 左侧面板：基础信息输入
  - 角色名称（带实时验证）
  - 性别选择（男/女）
  - 职业选择（剑客、刀客、枪客、弓手、法师、道士、刺客、医师）
  
- 右侧面板：MetaHuman外观编辑器
  - 皮肤编辑（颜色、粗糙度、次表面散射）
  - 眼睛编辑（虹膜颜色、瞳孔大小、湿度）
  - 发型编辑（发根/发梢颜色、粗糙度、各向异性）

- 底部按钮栏
  - 随机生成按钮：随机生成角色名和职业
  - 取消按钮：返回角色选择界面
  - 创建角色按钮：提交创建请求

### 2. CharacterCreationSceneController
**位置**: `Game/UI/Character/CharacterCreationSceneController.cs`

**功能**:
- 管理IntegratedCharacterCreationUI的生命周期
- 监听场景切换事件
- 处理角色创建成功/取消回调
- 与CharacterService交互

## 使用方法

### 在Flax Editor中设置

1. **创建角色创建场景**：
   - 打开Flax Editor
   - 创建新场景或使用现有场景
   - 场景命名为 `CharacterCreation`

2. **添加UI Canvas**：
   ```
   - 在场景中创建Empty Actor
   - 命名为 "CharacterCreationUI"
   - 添加 UICanvas Script
   ```

3. **添加控制器脚本**：
   ```
   - 选中 "CharacterCreationUI" Actor
   - 添加 CharacterCreationSceneController Script
   ```

4. **设置场景切换**：
   - 确保UIStateManager已正确配置
   - CharacterSelectionUI中"创建角色"按钮应调用：
     ```csharp
     UIStateManager.Instance.TransitionToScene(SceneType.CharacterCreation);
     ```

### 代码集成示例

```csharp
// 在CharacterSelectionUI中添加创建角色按钮
var createButton = new Button
{
    Text = "创建新角色",
    // ... 其他属性
};
createButton.Clicked += () =>
{
    UIStateManager.Instance.TransitionToScene(SceneType.CharacterCreation);
};
```

### 处理创建成功回调

角色创建成功后会自动：
1. 调用 `CharacterService.SelectCharacter(character)` 选中新角色
2. 切换到 `SceneType.CharacterSelection` 场景
3. 刷新角色列表

## 数据流

```
用户输入基础信息
    ↓
调整MetaHuman外观
    ↓
点击"创建角色"按钮
    ↓
验证输入 (角色名2-12字符)
    ↓
显示加载指示器
    ↓
调用 CharacterService.CreateCharacterAsync()
    ↓
发送网络请求 CreateCharacterRequest
    ↓
等待服务器响应 CreateCharacterResponse
    ↓
【成功】
    ├─ 触发 OnCharacterCreated 事件
    ├─ 选中新创建的角色
    └─ 切换回角色选择场景
【失败】
    └─ 显示错误消息
```

## 故障排除

### 问题1: UI不显示
**检查**:
- UICanvas是否正确添加到场景
- CharacterCreationSceneController是否附加到正确的Actor
- 场景类型是否匹配 (SceneType.CharacterCreation)

**解决**:
```csharp
// 在CharacterCreationSceneController.OnStart()中添加日志
Debug.Log($"UICanvas found: {uiCanvas != null}");
Debug.Log($"GUI found: {uiCanvas?.GUI != null}");
```

### 问题2: MetaHuman编辑器无法交互
**检查**:
- MetaHumanEditorUI是否正确初始化
- AppearanceEditor和PreviewController是否设置

**解决**:
```csharp
// 确保MetaHumanEditorUI的依赖项已正确创建
if (_metaHumanEditor.AppearanceEditor == null)
{
    Debug.LogWarning("AppearanceEditor未初始化");
}
```

### 问题3: 创建按钮一直禁用
**检查**:
- ValidatedTextBox的验证逻辑
- UpdateCreateButtonState()是否被调用

**解决**:
```csharp
// 添加调试日志
private void UpdateCreateButtonState()
{
    bool isValid = _nameInput.IsValid && 
                  !string.IsNullOrWhiteSpace(_nameInput.Text);
    
    Debug.Log($"Name valid: {_nameInput.IsValid}, Text: {_nameInput.Text}");
    _createButton.Enabled = isValid;
}
```
