# Horizon.Game.Message 模块

## 概述

Horizon.Game.Message 是为武侠MMORPG游戏设计的网络消息系统。该模块定义了游戏中各种交互所需的消息类型，包括账户管理、角色操作、战斗系统、社交功能、物品交易、技能系统等。

## 消息系统架构

### 核心组件

1. **MessageUnion** - 所有消息类型的基类，使用 MemoryPackUnion 注解实现多态序列化
2. **INetworkMessage** - 网络消息接口，定义了消息的基本属性
3. **MessageType** - 消息类型枚举，标识不同种类的消息
4. **ServiceType** - 服务类型枚举，标识消息所属的服务模块

### 序列化技术

- **MemoryPack**: 高性能的序列化库，用于快速序列化/反序列化消息
- **Orleans**: 用于分布式系统的序列化注解

## 消息分类

### 1. 账户与角色管理消息 (1-99)
- 登录/登出
- 角色创建/删除/选择
- 角色信息管理

### 2. 游戏核心玩法消息 (100-299)
- 移动同步
- 战斗系统（攻击、技能、伤害、死亡等）
- 轻功、内功等武侠特色系统

### 3. 社交与门派系统消息 (300-499)
- 门派、帮派管理
- 好友、组队、聊天
- PK、决斗等PVP功能

### 4. 物品与交易系统消息 (500-699)
- 背包、装备管理
- 交易、商店、拍卖行
- 物品制作、强化等

### 5. 技能与武学系统消息 (700-899)
- 技能学习、升级
- 武功秘籍
- 心法、经脉等

### 6. 任务与成就系统消息 (900-1099)
- 任务管理
- 成就、称号系统
- 图鉴收集

### 7. 系统与管理消息 (1100-1299)
- 心跳、状态监控
- 系统通知、公告
- 错误处理

### 8. 扩展消息 (1300+)
- 玩家同步消息
- 世界状态同步
- 门派、帮派、武学等扩展功能
- 管理员命令和系统管理

## 新增消息类型详解

### 基础游戏消息

#### PlayerSyncMessage
用于同步玩家的基础状态信息，包括位置、生命值、法力值、等级、职业等。

#### WorldStateSyncMessage
用于同步整个游戏世界的当前状态，包括世界时间、天气、事件、玩家、NPC和物品掉落等。

#### NpcSyncMessage
用于同步NPC的状态信息，包括位置、生命值、等级、行为状态和仇恨列表等。

#### ItemDropMessage
用于处理物品掉落逻辑，包括掉落位置、时间、来源和可拾取玩家等信息。

### 系统管理消息

#### SystemCommandMessage
用于管理员命令的发送和执行，包含命令参数、执行者信息等。

#### ServerManagementMessage
用于服务器管理操作，如重启、关闭、维护模式切换等。

#### PlayerManagementMessage
用于玩家管理操作，如封禁、踢出、权限设置等。

#### GameEventMessage
用于游戏事件的通知和管理，如玩家升级、获得成就等。

### 武侠特色消息

#### SectInfoMessage
用于门派信息管理，包括门派成员、技能、威望等。

#### GuildInfoMessage
用于帮派信息管理，包括帮派成员、技能、资金等。

#### MartialArtsManualMessage
用于武功秘籍系统，包括秘籍品质、类型、威力系数等。

#### WuXingSystemMessage
用于五行系统，包括金木水火土五种属性及其相生相克关系。

## 使用指南

### 创建新消息类型

1. 在适当的命名空间下创建新消息类
2. 继承 MessageUnion 和 INetworkMessage 接口
3. 添加 [MemoryPackable] 和 [GenerateSerializer] 注解
4. 使用 [MemoryPackOrder] 和 [Id] 注解标记属性
5. 在 MessageUnion 中添加相应的 [MemoryPackUnion] 注解
6. 在 MessageType 枚举中添加相应类型

### 消息处理流程

1. 客户端/服务端创建消息实例
2. 序列化消息并通过网络传输
3. 接收方反序列化消息
4. 根据 MessageType 分发到相应的处理器
5. 处理完成后可能返回响应消息

## 性能优化

- 使用 MemoryPack 实现高效的序列化/反序列化
- 消息类型预分配，减少运行时反射开销
- 合理设计消息结构，减少网络传输的数据量
- 消息池复用，减少GC压力

## 注意事项

- 所有消息类型必须继承 MessageUnion
- 消息字段应使用适当的数据类型以优化性能
- 遵循命名约定，保持代码一致性
- 在添加新消息类型时，务必更新 MessageUnion 的联合注解
