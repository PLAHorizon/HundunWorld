# 第三人称相机魔兽世界风格改造方案

日期：2026-10-25  
状态：待决策，尚未修改运行时代码

## 1. 目标与验收口径

目标不是再叠加一套“自动运镜”，而是把普通第三人称相机改成**轨道角度由玩家掌握、位置跟随角色、碰撞只压缩臂长**的稳定结构：

1. 不操作鼠标时，WASD、点击移动、起跑、停步、服务端位置校正均不得主动改变相机 Yaw/Pitch。
2. 左键拖拽只观察，不改变角色朝向；右键拖拽控制视角并按选定口径控制角色朝向。
3. 左右键手势可以组合、交错松开，不丢输入、不永久隐藏光标、不错误触发点选。
4. 滚轮只改变期望臂长；墙体遮挡只改变实际臂长，不把玩家俯仰角改成系统预设值。
5. 统一“相机轨道 Yaw”与“角色面向 Yaw”的符号，客户端预测、服务端输入、远端显示使用同一角色朝向。
6. 保留 Tab 锁定、Shift+Tab 候选循环、处决/剧情接管和显式复位；这些系统可以接管视角，但必须互斥，不与普通跟随同帧抢写。

## 2. 现状盘点与根因证据

### 2.1 直接触发源：移动自动对齐默认开启

- `HundunWorld/Source/Game/ThirdPersonCamera.cs:409-429`：`EnableAutoAlign=true`、延迟 2 秒、速度 90°/秒。
- `HundunWorld/Source/Game/ThirdPersonCamera.cs:1129-1132`：每帧执行自动对齐。
- `HundunWorld/Source/Game/ThirdPersonCamera.cs:2625-2668`：角色持续移动且超过延迟后，根据角色朝向修改相机 Yaw。
- `HundunWorld/Source/Game/ThirdPersonCamera.cs:2675-2718`：自动对齐直接写 `Yaw` 与 `_smoothYaw`。

因此，“没有转镜头、持续移动后镜头自己转”是当前代码的主动行为，不是角色父子变换导致。

### 2.2 符号反馈：相机与角色朝向约定相反

相机轨道偏移为 `(h·sin(Yaw), …, -h·cos(Yaw))`；相机看向焦点的水平前向对应角色面向角 `-Yaw`。文件内自动对齐已经按这个关系求“角色背后”的机位：

- `HundunWorld/Source/Game/ThirdPersonCamera.cs:2655-2662`：`相机 Yaw = -角色 Yaw`。

但正常移动输入却原样传递相机 Yaw：

- `HundunWorld/Source/Game/PlayerController.cs:779-803`：`LookYaw = Camera.Yaw`。
- `Horizon.Game.ECS.Arch/Systems/LocalSimulationSystem.cs:188-196`：`pred.Yaw = input.LookYaw`。
- `HundunWorld/Source/Game/LocalPlayerActorSyncSystem.cs:149-151`：预测 Yaw 写回角色 Actor。

组合后形成 `相机 Yaw → 角色 Yaw → 自动对齐取反 → 新相机 Yaw` 的反馈环。点击移动另走 `Atan2(direction.X, direction.Z)`（`PlayerController.cs:1304-1348`），所以 WASD 与 Alt+点击移动还可能出现不同表现。

### 2.3 其他非玩家主动的角度/距离写入者

- 智能避障：`ThirdPersonCamera.cs:1288-1320`，受阻且距离过近时把实际俯仰改为 `SmartAvoidancePitch=45°`。
- 状态过渡：`ThirdPersonCamera.cs:2902-2967`，切换战斗、游泳、飞行等状态时写 Distance/Pitch。
- 弹性跟随：`ThirdPersonCamera.cs:1154-1227` 当前只平滑焦点，不再自行旋转 Yaw；不是本次根因。
- 锁定目标、处决、剧情、R 复位是显式或独立模式，应保留并纳入所有权规则。
- 场景/Prefab 中相机是独立 Actor，不是玩家子节点；无需通过改父子关系修复。

### 2.4 输入冲突

- 当前只有右键拖拽转视角：`ThirdPersonCamera.cs:1762-1785`。
- 左键按下立即点选：`HundunWorld/Source/Game/Selection/WorldSelectionService.cs:124-147`。
- Alt+左键用于点击移动；Tab 已由用户明确分给相机 LockOn，不能改走选中系统。
- 当前没有“左右键同时按住向前移动”。

## 3. 推荐交互明细

### 3.1 鼠标手势

| 手势 | 推荐行为 |
|---|---|
| 左键短按后松开 | 保留世界点选；Alt+左键继续点击移动 |
| 左键按住并拖动 | 只旋转相机，不改变角色朝向，不触发点选 |
| 右键按住并拖动 | 旋转相机，同时让角色面向相机水平前方 |
| 左右键同时按住 | 角色向前移动；拖动仍按右键转向语义处理 |
| 先左后右 / 先右后左 | 后按键加入手势，不能取消前一按键状态 |
| 松开其中一个 | 只结束该键职责；另一键仍按住时保持其拖拽/移动语义 |
| 松光全部 | 恢复光标；若本次左键是拖拽，不补发点选 |
| 滚轮 | 调整期望距离，UI 捕获时让给 UI |
| R | 显式恢复角色背后基准机位，不与自动对齐混用 |

建议点击/拖拽阈值为 **5 个屏幕像素**；阈值只裁决“松开是否算点击”，拖动旋转从按下后即可累计，避免低速拖动被吞。

### 3.2 角度与移动所有权

普通状态建立单向数据流：

```text
鼠标增量 → 相机轨道 Yaw/Pitch
相机轨道 Yaw → 经统一负号转换 → 角色观察朝向（仅右键转向时）
移动输入 + 选定移动参考系 → 世界移动方向 → 点击移动/移动朝向规则
角色位置 → 平滑焦点 → 轨道机位 → 碰撞后的实际机位
```

禁止再从角色位置、角色速度或角色朝向被动反写普通状态的 Yaw/Pitch。移动只影响焦点和实际距离。

### 3.3 推荐默认参数

| 参数 | 推荐值 | 理由 |
|---|---:|---|
| 初始期望距离 | 500 cm | 沿用当前场景实测机位 |
| 距离范围 | 200–2000 cm | 沿用当前场景配置 |
| 聚焦高度 | 120 cm | 沿用当前厘米模型配置 |
| 鼠标灵敏度 | 0.20°/像素 | 先沿用现状，避免同时改变肌肉记忆 |
| Pitch 范围 | -60°–75° | 保留仰视与俯视，减少极端贴地/翻顶姿态 |
| 点击/拖拽阈值 | 5 px | 区分点选与观察拖拽 |
| 被动自动对齐 | 关闭 | 消除移动中自转 |
| 智能避障改 Pitch | 关闭 | 碰撞只缩短臂长 |
| 位置惯性 | 关闭 | 避免停步后焦点继续漂移 |
| 速度动态 FOV | 关闭 | 避免加减速产生“镜头在动”的错觉 |
| 位置跟随 | 轻量平滑，快速移动不落后超过约 30 cm | 保留质感但不制造横向摆动 |
| 碰撞收近 / 恢复 | 快速收近、约 0.20–0.30 s 平滑恢复 | 防穿墙且避免突然拉远 |

状态切换不得把玩家已经手动设置的 Pitch/Distance 重置为米制模板默认值。Normal/战斗普通状态共用玩家视角；LockOn、Cutscene、Execution 等显式模式可另设过渡。

## 4. 代码改造分层

### A. 先修正确性：稳定普通轨道

1. 普通状态默认禁用移动自动对齐；删除其对普通移动的速度驱动入口，显式 `ResetToBaseline()` 保留。
2. 统一转换函数：相机前向对应的角色 Yaw 使用 `-ThirdPersonCamera.Yaw`；正常输入与备用输入包必须走同一转换，点击移动朝向继续独立覆盖。
3. 普通碰撞只产出 `effectiveDistance` 与必要的高度安全约束，不再把 `effectivePitch` 改为预设角。
4. 把角度规范化、最短角差、相机 Yaw→角色 Yaw 转换集中为可测试的纯计算，避免多处各写一套符号。

### B. 重建鼠标手势仲裁

1. 在 `ThirdPersonCamera` 中分别记录左键、右键的世界起手、拖拽位移、光标捕获和组合状态。
2. 对外提供只读手势状态，供 `PlayerController` 处理“双键向前”和右键角色转向，供点选入口判断“本次是否拖拽”。
3. 点选从“按下立即选中”调整为“世界内按下记录、未超过 5px 且松开时选中”；Alt 点击移动保持优先。
4. 所有提前返回、Target 丢失、脚本 Disable、外部接管、菜单打开都统一释放光标与手势。
5. 保持 UI 起手不转镜头；世界起手后划过 UI 可持续到松手。

### C. 收敛自动运镜

1. Normal/Combat 的普通移动不自动改 Yaw/Pitch，不用速度动态 FOV。
2. 状态机只保留确有玩法意义的距离/肩部/锁定过渡；玩家手动视角优先。
3. LockOn、BossBattle、Cutscene、Execution 期间自动对齐不得运行；退出时恢复的是玩家之前的轨道角，而不是根据角色再猜一个角。
4. 外部接管结束后重置速度/焦点/碰撞缓存，避免恢复首帧跳变。

### D. 可观测性与回归入口

增加一组默认关闭的诊断计数/快照：`inputOwner`、`gesture`、`desiredYaw/Pitch`、`characterYaw`、`desired/effectiveDistance`、`collisionState`、`overrideOwner`。只在值变化或低频采样时输出，不逐帧刷屏。

自动验证至少覆盖：

1. **静止基线**：无输入 300 帧，Yaw/Pitch 完全不变。
2. **移动不变量**：固定视角前进、后退、横移、斜向各 3 秒，Yaw/Pitch 与基线一致；不能只断言最终位置。
3. **符号对照**：相机 Yaw=0/30/180/330° 时，角色前向与相机水平前向点积约为 1；点击移动与右键转向使用同一 Flax 朝向定义。
4. **左右键职责**：左拖不改角色朝向；右拖按选定口径改变；双键移动；交错松键后状态正确。
5. **点击回归**：4px 松开仍点选，6px 拖动不点选；UI 起手不点选、不旋转；Alt+点击移动不变成点选。
6. **碰撞回归**：同一 Yaw/Pitch 下遮挡只缩短距离；遮挡消失平滑恢复，不改玩家角度。
7. **模式互斥**：LockOn/处决/剧情接管与恢复各跑一遍，无第二个写入者抢角度。
8. **帧率对照**：30/60/120fps 下跟随和复位不产生不同方向的净旋转。
9. **真实 PIE**：用现有 `DebugMoveForward` 走真实 ECS 预测链，记录相机和角色角度；编译成功不代替运行验证。

## 7. 已确认决策

用户已于 2026-10-25 逐项确认：

1. **被动自动对齐**：普通移动彻底关闭；无鼠标输入时 Yaw/Pitch 不变。
2. **鼠标完整度**：采用完整 WoW 双键手势；左拖只转相机，右拖同时控制角色朝向，双键向前，短按左键保留点选。
3. **键盘移动参考系**：W/S 沿角色前后，A/D 平移；左拖观察不改变行进方向。
4. **避障与动态效果**：普通状态只缩臂、固定 FOV、关闭惯性，不自动抬高俯角。
