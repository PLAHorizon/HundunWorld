## 1. 总体架构与数据流

### 1.1 技术栈

| 层 | 技术 | 版本/说明 |
|---|---|---|
| 传输 | TouchSocket（TCP，无 UDP/KCP 通道） | 4.1.1，网关监听 0.0.0.0:7789 |
| 序列化 | MemoryPack + LZ4（快照 >256B 自动压缩） | 1.21.4 / K4os 1.3.8 |
| 服务端框架 | Microsoft Orleans（Grain turn-based） | 10.0.1 |
| 客户端逻辑 | Arch ECS（`Horizon.Game.ECS.Arch`） | 2.0.0-beta + Arch.System 1.1.0 |
| 客户端渲染 | Flax Engine 1.12 | Actor / AnimatedModel 桥接 |
| 运行时 | .NET 10 | SDK 10.0.300 |

### 1.2 端到端数据流（核心不变量）

```
[客户端]
PlayerController → PlayerInputComponent
  → LocalSimulationSystem（FixedUpdate 60Hz 本地预测）
  → InputSendSystem（NetworkSend：打包 + 冗余重传）→ ECSUpdateDriver → TouchSocket 上行
[Gateway]
GameNetworkServer（TCP 接入）→ SyncPacketHandler（路由/去重）
  → PlayerSessionGrain / ZoneShardGrain（Orleans 调用）
[服务端权威]
ZoneShardGrain.TickAsync（60Hz 权威模拟）
  → MovementValidator 回放校验（MovementFormula 确定性数学）
  → 偏差>阈值 → CorrectionPacket；否则更新权威位置
  → 20Hz 增量快照广播（每 60 tick 强制全量）→ P-F1 批量 fanout
  → GatewaySyncDispatcher（带宽守门 + 按 session 路由）→ TouchSocket 下行
[客户端呈现]
SnapshotReceiveBuffer → SnapshotApplySystem（NetworkReceive）
  → 本地玩家：PredictedTransformComponent（预测路径）
  → 远程实体：InterpolatedTransformComponent（插值路径）
  → InterpolationSystem（Render，状态机 + 前向预测 + 缓冲时间插值）
  → FlaxActorSyncSystem（ECS→Actor）/ LocalPlayerActorSyncSystem（预测→Actor）
[本地玩家校正]
InputAck → 清理输入历史；Correction → ReconciliationSystem（权威重放 + SmoothDamp 追平）
```

**混合 netcode 模型**：本地玩家走**客户端预测**（低延迟），远程实体走**快照插值**（平滑一致），服务端 `ZoneShardGrain` 通过 `MovementValidator` 保持**权威**（反作弊 + 最终一致性）。这是全系统设计的核心不变量。

### 1.3 项目分层依赖（网络同步相关）

| 项目 | 职责 |
|---|---|
| `Horizon.Game.Message` | ★ 客户端/服务端**共享协议**：SyncPacket union、帧编解码、同步组件、客户端分派器 |
| `Horizon.Game.Core` | 服务端可复用纯逻辑：MovementFormula/Validator、GatewaySyncDispatcher、AOI 数据结构、重连编排 |
| `Horizon.Game.ECS.Arch` | 客户端 Arch ECS 实现：7 个同步系统 + 7 个网络缓冲 + 同步组件 |
| `Horizon.Game.Gateway` | TCP 网关、SyncPacket 路由、fanout observer/source 适配、带宽守门 |
| `Horizon.Orleans.Interface/Grains` | Grain 契约与实现（ZoneShardGrain / PlayerSessionGrain / IWorldDiffLogGrain 等） |
| `HundunWorld/Source` | Flax 客户端：NetworkManager、26 个 Handler、ECSUpdateDriver、Actor 桥接 |

## 2. 传输层与协议

### 2.1 双层帧格式

1. **内层** `SyncPacketCodec`（`Horizon.Game.Message/Sync/SyncPacketCodec.cs:21-169`）：
   `[Kind 1B][Compression 1B][PayloadLength 4B][Payload]`（共 6B 帧头）。`SnapshotPacket` 原始字节 ≥256B 时 LZ4 压缩（`SnapshotCompressionThreshold`，`:24`），输入包**永不压缩**保延迟；解压设 `MaxDecompressedSize=4MB` 防解压炸弹（`:28`）。帧从 `ArrayPool` 借出，`ReturnFrame` 归还。
2. **外层** `HorizonMessageAdapter.PackMessage` 8 字节线路帧（`Horizon.Game.Message/Network/HorizonMessagePacket.cs`），同步包 `compress:false`（延迟敏感）。

### 2.2 协议版本（`SyncPackets.cs:12-54`）

`SyncProtocolVersion.Current = 8`，`MinimumSupported = 5`。版本演进记录在源码注释中：
- **v4**：`InputPacket` 显式携带 `CharacterId`（修复单例 Handler 实例字段被多连接共享覆盖）；
- **v6**：`InputPacket` 新增 `MaxSpeed`（修复两端固定 6 m/s 推进、速度未进同步链路的问题）；
- **v7**：`BaselineResyncRequestPacket`（baseline 失配时主动请求全量重传）；
- **v8**：链路归一重构 + 超大规模容量治理（带宽预算限流 + 兴趣分级 + 客户端规模档位）。

### 2.3 SyncPacket union（17 种包，`SyncPackets.cs:100-127`）

`Kind` 枚举（Unknown=0 占位）与 `MemoryPackUnion` tag 存在**偏移 1** 的对应关系（注释明确说明 tag 从 0 连续，`InteractionSync=9 → tag 8`）：

| Kind | 包 | 方向 | 用途 |
|---|---|---|---|
| 1 | HandshakePacket | 双向 | 协议版本 + 本地玩家身份 + 初始位置 |
| 2 | SnapshotPacket | S→C | baseline(全量)/delta(增量) 快照 |
| 3 | InputPacket | C→S | 预测输入（ClientTick + 预测终点 + MaxSpeed） |
| 4 | EventPacket | S→C | 离散事件（技能/伤害/死亡/Correction/InputAck 载荷） |
| 5 | WorldChunkDiffPacket | S→C | 世界 diff 流，PayloadType 复用承载 5 类载荷 |
| 6 | WorldPatchManifestPacket | S→C | 世界补丁清单/版本向量 |
| 7 | InputAckPacket | S→C | 输入确认（LastProcessedClientTick） |
| 8 | ReconnectResumePacket | C→S | 断线续连（三路版本向量） |
| 9 | InteractionSyncPacket | 双向 | 交互槽状态（StateBits 高低位区分上下行意图） |
| 10 | SceneObjectSyncPacket | 双向 | 场景对象状态（宝箱/门/开关） |
| 11 | SubscriptionUpdatePacket | 双向 | AOI chunk 订阅变更 |
| 12 | HandshakeRejectPacket | S→C | 版本过低拒绝 |
| 13-15 | CombatAction/Damage/DeathPacket | 战斗 | 攻击请求/伤害/死亡 |
| 16 | BaselineResyncRequestPacket | C→S | baseline 缺失重传请求 |

`WorldChunkDiffPayloadType`（`:407-419`）：EntityDelta=0 / InteractionSync=1 / Event=2 / Correction=3 / SceneObjectSync=4。

### 2.4 同步组件（`Sync/Components/SyncComponents.cs`，423 行）

`EntityDelta` 承载 4 个可选字段（`SyncPackets.cs:308-330`）：`Identity`（NetworkIdentityAuthComponent）、`Transform`（AuthTransformComponent）、`State`（EntityStateAuthComponent）、`MovementState`（MovementStateAuthComponent）、`AnimationState`（AnimationStateAuthComponent）。

**频率策略**（`CharacterSyncConfig.cs`）：
| 同步类型 | 频率 | 触发 |
|---|---|---|
| Transform | 20Hz（50ms） | 每 tick 必带 |
| MovementState | 10Hz（100ms） | 心跳 + 变化触发 |
| AnimationState | 事件驱动 | 仅 Montage 触发/结束 |
| EntityState 扩展 | 1Hz（1s） | 心跳 + 变化触发 |

`EntityStateAuthComponent` 扩展后含 Health/MaxHealth/StateBits/Mana/MaxMana/Level/Exp/Stamina/MaxStamina，新字段 `[MemoryPackOrder]` 从 3 起连续编号保持向后兼容。

## 3. 客户端预测 + 服务端权威（核心 netcode）

### 3.1 客户端预测链路（60Hz 固定步长）

1. **输入采集**：`PlayerController`（Flax Script）写 `PlayerInputComponent`（MoveX/MoveY/LookYaw/LookPitch/InputBits/MaxSpeed/JumpPressedThisFrame）。
2. **本地模拟** `LocalSimulationSystem`（`Horizon.Game.ECS.Arch/Systems/LocalSimulationSystem.cs`，FixedUpdate order 10）：查询 `[PlayerInputComponent + NetworkIdentityComponent(IsLocalPlayer) + PredictedTransformComponent]`，本地玩家每帧 `CurrentClientTick++`；跳跃边沿触发（普通跳 5.5 冲量，轻功三段 5.5/4.5/3.5）；调 `MovementFormula.Step` 推进；`GroundHeightSampler`（Flax `Physics.RayCast` 注入）做地面吸附，采样失败且前 120 帧保护期内冻结垂直位置防坠空（`:160-186`）；跨 chunk 时触发 `PlayerChunkChanged` 事件做 AOI 动态订阅（滞后防抖 8 chunk ≈ 128m，`HundunWorldGame.cs:1211-1272`）。
3. **输入打包** `InputSendSystem`（NetworkSend order 0）：生成 `InputPacket{ClientTick, CharacterId, InputBits, LookYaw/Pitch, MoveX/Y, PredictedEndX/Y/Z, MaxSpeed}` 入队 `InputSendQueue`；同步写 `InputHistoryBuffer`（容量 256 环形）供回滚重放。
4. **发送出口** `ECSUpdateDriver.FlushInputSendQueue`：握手未完成前一律丢弃；经 `GuardSyncSender.SendLocalAsync`（SyncGuard 受控发送）编码发送。

**关键**：`InputPacket.MaxSpeed`（v6）让客户端每帧上送目标速度（含 Run/Sprint/Crouch 倍数），服务端权威回放与客户端预测用**同一速度值**调 `MovementFormula.Step`，这是两端一致性的前提。

### 3.2 确定性移动数学（`Horizon.Game.Core/Sim/MovementFormula.cs`，133 行）

- 纯静态、禁 SIMD、运算顺序固定，`FormulaVersion = 2`（两端不一致视为协议不兼容）。
- `Gravity=9.81`、`TerminalVelocity=50`、`DefaultMaxSpeed=6`。
- `StepHorizontal` 先夹紧输入 [-1,1] 再归一化；`StepVertical` 跳跃冲量 + 重力积分 + 终端速度截断。

### 3.3 服务端权威回放（`MovementValidator.cs:112-387`）

`ZoneShardGrain.TickAsync` 对每个有 `PendingInputs` 的实体：
1. 输入间隙吸附：首输入 `ClientTick > LastProcessed+1` 时吸附到该输入 PredictedEnd 并跳过首帧重放（避免双倍位移过冲，`ZoneShardGrain.cs:923-932`）。
2. 从权威起点按 ClientTick 升序逐帧回放（60Hz 步长），跟踪 maxObservedSpeed / jumpCount / isGrounded。
3. 输出权威终点 + 可选 `CorrectionPacket`。

**判定阈值**（`MovementValidator.Options`，`:34-75`）：

| 阈值 | 默认 | 触发 |
|---|---|---|
| `PositionEpsilon` | 0.5 m | drift 超阈值 → PredictionDrift 修正 |
| `HardSpeedCap` | 200 m/s | MaxSpeed 超上限 → SpeedHackSuspected |
| `MaxAcceleration` | 50 m/s² | 速度变化率超限（防变速） |
| `TeleportDistanceThreshold` | 100 m | 位置跳变（防瞬移，合法传送走独立协议） |
| `RttScalingFactor` | 0.002 m/ms | 动态阈值 = epsilon + factor×rttMs（RTT=300ms 放宽 0.6m，上限 2m） |
| `MaxJumpCount / MaxQinggongJumpCount` | 2 / 3 | 跳跃次数上限 |
| `TickDtSeconds` | 1/60 | 回放步长 |

**原因优先级**：PredictionDrift > SpeedHackSuspected > JumpCountExceeded（`:351-362`）。`CorrectionPacket` 携带 `LastProcessedClientTick`，客户端据此清理已确认输入、避免「吸附+重放死循环」。

### 3.4 客户端回滚修正（`ReconciliationSystem.cs`，FixedUpdate order 20）

每帧两步：
1. **ProcessInputAck**（`:146-163`）：从 `InputAckReceiveBuffer` 取最新 ACK，记录 `_lastAckedClientTick`，仅清理 `InputHistoryBuffer` 已确认输入（不重放，避免双重移动）。
2. **ProcessCorrection**（`:172-425`）：修正风暴抑制（2s 内 >5 次进 1s 冷却）；drift > 0.5m 才修正；过期 Correction 检测（`LastProcessedClientTick < _lastAckedClientTick` 则跳过）；从权威位置 + `InputHistoryBuffer` 未确认输入**逐帧重放**得到正确预测目标；`SmoothDamp3`（临界阻尼，smoothTime≈0.067s）平滑追平。

### 3.5 上行去重（防重放/防重复模拟）

**Gateway 双层去重**（`SyncPacketHandler.HandleInputAsync`）：
1. **握手基线**：`ClientTick < handshakeBaseline` 判旧会话残留丢弃；基线从 `InitialClientTick` 记录，>1000000 视为 Unix 时间戳重置为 0（`:279-281`）。
2. **单调去重**：`(characterId, connectionId)` 复合 key 记录已接受最大 ClientTick，`<=` 判 Duplicate 返回最新 ack 不转发（复合 key 修复自动重连后输入被持续拒绝的问题，`:157-163`）。

**会话态第二层**（`PlayerSessionState.AcceptInput`）：`ClientTick <= LastAccepted` → Duplicate；`ServerTick - ClientTick > MaxInputLagTicks(600)` → TooOld（防攒包重放）；环形缓冲容量 256。

**转发优化 P-F3**：优先 `ReceiveInputAndForwardAsync`（单 grain turn 完成 Accept→转发→Consume→BuildInputAck，RTT 3 次降 1 次），失败回退三段式。

## 4. 快照插值（远程实体）

### 4.1 快照应用（`SnapshotApplySystem.cs`，NetworkReceive order 10，1437 行）

- **缓冲消费**：单帧上限 `MaxSnapshotsPerFrame=32`，超限丢弃旧快照但**抢救其中的 Spawn/Despawn 生命周期 delta** 本帧优先应用（`_pendingLifecycleDeltas`，丢失生命周期会导致实体永久缺失，`:543-586`）。
- **全量/增量**：`BaselineTick==0` 全量——与 `_lastAppliedSnapshot` 按同 tick 合并（upsert by EntityId，修复 chunk 拆包覆盖语义）；`BaselineTick!=0` 增量——baseline 不匹配时入队 `BaselineResyncRequestPacket` 请求全量重传，匹配时**只处理本次增量 delta**（修复重复处理 baseline 导致角色闪退，`:672-716`）。
- **Spawn**：维护 `_entityIdToArchEntity` 字典；重复 Spawn 时远程实体转插值目标更新（不销毁重建）、本地玩家仅更新 AuthTransform、其他销毁重建；无条件检测同 EntityId 已存在的本地玩家实体并**收养**（修复双实体导致每帧双 InputPacket、角色不动）；新实体按 IsLocalPlayer 分支挂 `PlayerInput+PredictedTransform`（本地）或 `InterpolatedTransform`（远程）。
- **Update**：本地玩家仅写权威 Transform（不覆盖预测位置，但不再 `return`，后续 MovementState/State/AnimationState 分支继续执行）；远程实体更新插值 Target + **快照环形缓冲** + Dead Reckoning 速度记录；NaN/Infinity 数据隔离（`InvalidSnapshotsSkipped` 计数，spec 5.3.1 规则 7）。
- **Despawn**：本地玩家保护（AOI 离开视野不销毁本地实体）；远程实体标 Offline 销毁。
- **超时清理**：孤儿映射（每 300 帧）+ 远程实体状态机 `Active→Idle(1s)→Stale(5s)→TimeoutDespawn(90s)`（`CleanupStaleEntities`），服务端异常断线检测需 19~65s，客户端 90s 兜底清理避免远程角色「卡住不动」。

### 4.2 插值推进（`InterpolationSystem.cs`，Render order 0，692 行）

**状态机驱动的五态插值**（`RemoteEntityState` 枚举）：

| 状态 | 进入条件 | 行为 |
|---|---|---|
| Initializing | 刚 Spawn | 保持位置等待首个 delta |
| Active | 收到 Update | 前向预测 + 线性 Lerp 修正 |
| Idle | 1~5s 无 delta | Dead Reckoning 按最后速度外推（最长 2s） |
| Stale | 5~90s 无 delta | 冻结等待恢复 |
| Offline/TimeoutDespawn | 销毁 | 不进入循环 |

**Active 状态 3 档传送处理**：
- 距离 ≤ 100m：普通 Lerp + 前向预测 `predictedTarget = Target + LastVelocityXZ × extrapTime`（消除「弹性带」渲染速度周期波动，目标 CV ≤ 0.3）；
- (100m, 500m]：**加速混合**——200ms smoothstep 缓动过渡（把瞬移变成可见的「快速冲刺」）；
- > 500m：**硬跳**（专处理复活/跨地图传送）。

**自适应插值延迟**（`SnapshotApplySystem.AdaptiveInterpolationDelaySeconds`）：`target = max(avgInterval + 2×jitter, rtt/2 + rttJitter)`，clamp 到 [0.1s, 0.2s]；RTT 用 EWMA（α=0.125）平滑，`RecordRttSample` 由 HeartbeatResponse/InputAck 驱动；基于 RTT 滞回切换 `NetworkQualityLevel`（Strong/Medium/Weak）。[A2] 引入 RTT 下限防缓冲抽干。

### 4.3 客户端 ECS 与 Flax 桥接

- `ECSUpdateDriver`（Flax Script）：`ECSManager.Update → ArchHost.Tick → FlushInputSendQueue → TickVisibilityAudit`（0.8s 可见性审计 + `ReconcileMissingActors` 补建）；注入诊断 Sink、远程同步阈值、`SyncScaleController` 规模档位。
- `FlaxActorSyncSystem`：订阅 `EntitySpawned/EntityDespawned` 创建/销毁远程 Actor；`MaxRemoteEntityCount=20` + 最远优先降级。
- `LocalPlayerActorSyncSystem`：每帧从 `PredictedTransformComponent` 写 Actor 位置/朝向（预测位置是本地玩家单一事实源）。

## 5. AOI 兴趣集

### 5.1 数据结构（`Horizon.Game.Core/World/ZoneShardAoi.cs`，165 行）

- 双向映射：`chunkToSessions: Dictionary<ulong, HashSet<long>>` + `sessionToChunks`；`MetresPerChunkCell = 16`（`WorldCoord.cs:15`），`ToChunkMortonKey` 用 MortonCodec 3D 编码。
- 广播扇出 `FanOut(targets)` 一次计算所有目标（`sessionId → payloadIndex 列表` 聚合）。
- **坐标系约定**：AOI 订阅用 ECS **Z-up**，快照 Transform 用 Flax **Y-up**，广播时须 `WorldCoord.ToChunkMortonKey(t.X, t.Z, t.Y)` 还原（`ZoneShardGrain.cs:2296`）。

### 5.2 订阅生命周期

- 握手时传**空数组**调 `EnterWorldAsync`，再 `UpdateSessionPositionAsync(x,y,z)` 让 grain 侧算 AOI 差异订阅——把 ~26000 个 ulong（~208KB）RPC 降为 3 个 float（`SyncPacketHandler.cs:319-333`）。
- `UpdateSessionPositionAsync`：Flax→ECS 转换后 `FillChunksInView(radius=28)`（185193 chunks，约 912m³）与旧订阅做差集后增量 Subscribe/Unsubscribe（`ZoneShardGrain.cs:528-566`）。
- 客户端跨界上行 `SubscriptionUpdatePacket`（有位置走位置驱动，否则 chunk 数组路径，`SyncPacketHandler.cs:868-892`）。

### 5.3 广播路径

`BroadcastSnapshotAsync` 按 chunk 分组序列化 delta → 查 `_aoi.GetSubscribers(chunkKey)` → P-F1 **批量通道**：一轮广播的 (diff, 受众) 累积到 `_fanoutBatchBuffer`，每个 observer 仅一次 `OnChunkDiffBatchAsync` 跨进程 RPC（`ZoneShardGrain.cs:797-824`）。Gateway 侧 `GatewayZoneShardFanoutSource` 实现 observer+source 双角色，中间有界 Channel（容量 8192，`DropOldest` 反压）。

### 5.4 实体生命周期广播

- `BroadcastEntityLifecycleAsync`（`ZoneShardGrain.cs:1781-1911`）：Spawn/Despawn **走全广播**（`GetAllSubscribers` 剔除触发方，修复跨 chunk 可见性与 Despawn 无人订阅问题）；仅 Spawn 时给触发方 session 补发全场已存在实体的 Spawn（含自己）。
- `EnterWorldAsync` 重连场景：实体已存在时跳过 Despawn+Spawn，仅重建 AOI 订阅 + 强制全量快照（修复「远程角色周期性闪退」）。
- 实体租约：`EntityLeaseDuration=30s`，网关每 20s `RenewLeaseAsync` 批量续约；孤儿清理每 3s 扫描。

## 6. 服务端权威模拟（ZoneShardGrain，3393 行）

### 6.1 tick 循环（60Hz，`ZoneShardGrain.cs:845-1387`）

- `RegisterTimer(1/60s)`；位置落库独立定时器（P-F5，每 5s）；孤儿清理每 3s。
- 每实体：输入间隙吸附 → `MovementValidator.Validate`（传 `EstimatedRttMs` 动态阈值）→ 速度计算（除以**真实回放帧数×dt**，防 N 帧积压时速度虚高 N 倍）→ 移动模式推导 → 加速度/瞬移检测（豁免静止→移动合法起停）→ `shouldBroadcast` 判定（变化即产出 Update delta；静止实体每 6 tick=100ms 心跳）。
- **广播降频**：`SnapshotBroadcastIntervalTicks=3` → 20Hz 广播（60Hz 全速广播时每 chunk 串行跨进程 RPC 导致 tick 超 16.7ms，这是「多客户端同步瓶颈」的修复产物）；输入/移动模拟保持 60Hz。
- **全量/增量判定**：`_lastSnapshot==null || 距上次全量≥60 tick || _forceFullSnapshotNextTick` → 强制全量（`BaselineTick=0`）。

### 6.2 增量编码（baseline/delta）

- **基线维护**：`_lastSnapshot` 保存「实际下发」状态（非全量 deltas）；生产路径用**持久字典 `_lastSnapshotDict`** upsert（方案5，消除每增量 tick O(N) 遍历重建）。
- **增量比对 `EntityDeltaChanged`**：Transform 阈值 0.01f；State 整数差异 ≥1；MovementState 任何变化；AnimationState 事件驱动。
- **心跳保护**：baseline 与 current 的 ServerTick 差 ≥6 tick（100ms）则强制纳入增量，绕过字段比对——解决静止实体被增量过滤导致客户端「莫名离线/闪现」。
- **chunk 聚合广播**：`_deltaByChunkBuffer` 分组 → 每 chunk 一次 MemoryPack 序列化（复用字段级 `_serializeBuffer` ArrayBufferWriter，方案1）→ `EnqueueFanoutDiff`。
- **Correction 广播**：封装为 `EventPacket(SyncEventKind.Correction)` 走事件通道（可靠+高优先级，不受 snapshot tick 限制）。
- **InputAck 双链路**：Gateway 直连响应为主，grain 每 3 tick 广播为安全网（`InputAckBroadcastIntervalTicks=3`），消除双链路重复确认。

### 6.3 状态持久化与位置双轨

- `ZoneShardState`（Entities: `Dictionary<ulong, SimulatedEntityState>`）持久化到 Orleans Storage；`OnActivateAsync` 恢复时用持久化权威位置回填瞬态字段，避免「角色回起点/误判瞬移」（`:277-296`）。
- `ICharacterPositionStore`（Redis `character:position:{id}`，永久）+ `CharacterGrain.UpdateLastPositionAsync` 每 60 tick 更新，双轨制。

## 7. Gateway 与带宽治理

### 7.1 GatewaySyncDispatcher（`Horizon.Game.Core/Sim/Server/GatewaySyncDispatcher.cs`，648 行）

- **纯 C# 逻辑**，不依赖 Orleans/TouchSocket：`IZoneShardFanoutSource`（拉取）→ 按 `TargetSessionIds` 查 `ISessionRegistry` → 经 `IClientPacketSink` 下发。
- **P-F2 转发优化**：移除每事件 Parallel.ForEach（MMORPG 单事件受众仅几个~几十个 session，并行调度开销 > 顺序发送）；每事件 `new HashSet<long>` 按 sessionId 去重（不能复用类级字段——多 worker 并发 Clear/Add 会竞态）。
- **Task 16**：一次编码 wireBytes 所有 session 复用（避免每 session 重复 `SyncPacketCodec.Encode + PackMessage`）。

### 7.2 带宽守门（100kbps 红线，`SessionBandwidthTracker`）

- **三级降级**：正常 20Hz → 限流 10Hz → 深度降级 5Hz；连续 3s 低于阈值逐级回升。
- **lock-free**（Task 17）：`Interlocked.Add` 累计字节 + `CompareExchange` 自旋滚动 1s 窗口；`kbps = bytes×8/1024/seconds`。
- **带宽估算**（`EstimatePacketSizeBytes`）：按包类型保守上界；压缩包按 0.6× 折减（修复 #18：不考虑压缩会触发虚假限流把正常 20Hz 降到 10Hz）。
- **方案3 闭环**（WIP）：`ShouldThrottleSession` 对 `WorldChunkDiff+EntityDelta` 做 per-session 定频过滤（按 `_dispatchTickCounter` 60/hz tick 间隔跳过），打破「发送>消费」正反馈循环；全量快照/Correction/InputAck/Event 等控制信道不过滤（保证自愈与控制信道畅通）。
- 诊断事件：`BandwidthThrottled` / `BandwidthRecovered`（吞异常）；`GetBandwidthSnapshot()` 供监控/Prometheus。

### 7.3 SyncDispatcherHostedService

fanout 订阅（`CreateObjectReference` 注册 observer + 30s 重订阅兜底）+ **多 worker** dispatch 循环（`SyncDispatcherHostedService.cs:183-212` 起多 worker 并发 `RunOnceAsync`）。

## 9. 弱网降级策略

### 9.1 JitterBuffer 自适应

RTT 滑动窗口 20 样本，EMA(α=0.2) 平滑 + 方差估计；自适应插值延迟窗口 clamp 到 [80ms, 200ms]：`Clamp(emaRtt×1.5 + sqrt(variance), 80, 200)`；两套算法并存（原 `ComputeRecommendedDelayMs`: 30-500ms 窗口）。

### 9.2 InputPacket 冗余重传

`InputSendSystem` 维护容量 64 未确认环形缓冲；`ClientTick - LastAckedClientTick > 5` 触发重传全部未确认输入；服务端按 ClientTick 去重。`_pendingLock` 保护 ECS 线程与网络 IO 线程并发访问。

### 9.3 断线重连（ReconnectResume 三路边界）

`ReconnectResumePacket` 携带：`LastAppliedSnapshotTick` / `LastAppliedDiffSeq` / `BaselineVersion + WorldPatchVersion`。

**服务端决策**（`PlayerSessionState.ApplyReconnect`，`Horizon.Game.Message/Sync/Server/PlayerSessionState.cs:208-237`）：

| 决策 | 触发条件 |
|---|---|
| ResumeIncremental | 版本向量兼容，仅落后少量 diff |
| RequireLauncherPatch | baseline/worldPatch 版本不匹配 |
| ResendFullChunks | 落后 diff 过多（> InputBufferCapacity×64） |
| ForceReLogin | 客户端 `LastAppliedDiffSeq > serverHead`（状态矛盾） |

**超时降级**：resume 失败回退全量快照重发；客户端 5s 未收到响应主动降级为全量握手。

**客户端断线策略**（`HundunWorldGame.OnConnectionStatusChanged`）：Reconnecting **不暂停**插值和 Actor 同步（防止远程角色不动）；断线不切换场景、不销毁 Actor；重连成功后靠服务端全量快照更新现有实体；60s 超时才退回角色选择界面。

### 9.4 心跳与 RTT 测量

`HeartbeatManager` 每 15s 发送（失败缩短到 5s）；`HeartbeatResponseHandler` 用 Stopwatch 计算 RTT → `SnapshotApplySystem.RecordRttSample`（EWMA α=0.125、抖动 β=0.25）驱动自适应插值延迟与网络质量等级；`ReconnectionManager.CheckHeartbeat` 每 3s 检查，超 30s 且连续 5 次才触发断线探查。

## 13. 技术债与风险点

1. **双通道并存**：客户端热路径由 `SyncPacketMessageHandler` + `HundunWorldGame` 事件桥接驱动，`SyncPacketDispatcher`（v2 管线）供新协议扩展与测试使用——两套分派管线并存，`docs/NETCODE.md` 标注「InteractStart/End/Stolen 事件不直接处理而是由 NetworkRuntime 显式路由」，易产生维护歧义。
2. **TCP 单通道**：无 UDP/KCP 分通道，所有消息（含高频快照）走可靠 TCP，弱网下队头阻塞（HOL）由「冗余重传 + 降频 + 缓冲插值」缓解但未根除。
3. **规模上限**：`ISyncInterestGradeStrategy` 三档分级与 `SyncScaleController` 规模档位（20/100/1000/5000）已实现但 `ShouldThrottleSession` 注释承认「无法在 dispatcher 侧区分全量快照与增量 EntityDelta」——全量快照不受定频过滤，极端带宽场景下自愈信道可能仍超预算。
4. **方案 6 插值延迟**：缓冲插值 `renderTick = latest - delayTicks` 依赖服务端 tick 间隔均匀的假设（`TrySnapshotBufferInterpolate` 注释），服务端广播降频 20Hz 时样本间 tick 间隔不均匀（广播 tick 与模拟 tick 分离），可能影响插值精度；代码回退逻辑已兜底。
5. **GroundHeightSampler 信任问题**：`MovementValidator` 未注入 `GroundHeightSampler` 时信任客户端 `PredictedEndZ`（仅 |dzPred|≥10m 不信任），是当前反作弊的已知弱环（注释标注为预留）。
6. **会话绑定校验部分为 TODO**：交互上行 `interactorId 与 characterId 一致`、`interactableId 存在性` 校验在源码注释中标注 TODO，目前依赖灰度开关。
7. **EntityLeaseDuration 30s**（方案5 缩短）：容错从 4 次续约失败降为 1 次，网关网络抖动 >20s 可能误判断线强制 Despawn——注释已说明「容错降低但可接受」，需弱网压测验证。
8. **重连宽限期**：`PlayerDespawnScheduler` 15s 宽限期 + 客户端 5s resume 超时降级 + 60s 断线超时，三者时间窗存在衔接窗口（15s~60s 之间断线重连的用户体验依赖服务端全量快照自愈）。

## 14. 结论

HundunWorld 的网络同步是**完整的自研混合 netcode**：客户端预测（60Hz 固定步长 + 确定性 MovementFormula）+ 服务端权威（Orleans ZoneShardGrain 60Hz 回放校验 + 反作弊多维度）+ 快照插值（五态状态机 + 前向预测 + 自适应延迟 + Mirror 式缓冲时间插值），叠加 AOI（Morton chunk 双向订阅）、带宽治理（100kbps 红线三级降频 + 方案3 定频闭环）、弱网降级（JitterBuffer + 冗余重传 + 三路重连）、增量编码（baseline/delta + 心跳保护 + 重传自愈）等工业级机制。协议层共享库（`Horizon.Game.Message`）与确定性数学（`MovementFormula`）是两端一致性的基石。

当前「1.0.4」在途改动聚焦 6 个方案解决超大规模下的 GC 压力（方案1/5）、Spawn 自愈（方案2）、带宽闭环（方案3）、去重可靠性（方案4）与快照抖动平滑（方案6），注释中对每个 ArrayPool 化取舍都有异步生命周期安全论证，工程严谨度高；按 commit 描述目前约完成 1/3，后续需补充的带宽/规模档位降级能力在 `docs/NETCODE.md` §14-15 与 `docs/TECH_DEBT.md` 中已有路线。
