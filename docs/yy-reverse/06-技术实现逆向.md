# 06 · 技术实现逆向（可见证据与推断）

> 声明：未接触客户端/服务端二进制。本文把“画面可直接证明的”与“从表现/公开资料推断的”严格分开；推断项均标注【推断】。  
> 公开资料只用于引擎/跨端等事实，不作为玩法结论的唯一依据。

## 1. 引擎与平台

### 1.1 引擎

【旁证】多家媒体与官方宣传：本作使用网易自研 **Messiah（弥赛亚）** 引擎；该引擎自 2013 年研发，支持动态全局光照、物理、动画、跨平台（PC/移动/主机），并有“动态全局光”相关专利表述。

【实证】画面表现与 Messiah 的宣传点一致：

- 大场景 + 高密度植被/建筑（P02、P24）；
- 时间/天气变化（P16 00:32 时辰盘；P24 夜间地图/灯光）；
- 布料/毛发/刺绣细节（P09 角色特写、P04 立绘）；
- 水面/雾气/体积光（P02 01:00 水面、P03 01:36 尘雾）；
- PC 端 1080p60 录制（主视频标题/格式），移动端同源 UI。

### 1.2 跨端

【旁证】PC/移动跨端互通；国际服上线后登顶多地区榜单；支持 DLSS 4/光追（媒体）。

【实证】UI 同时出现：

- PC 手柄提示：`LB`（防御）、`LT`、`RB`（P03 00:30、00:52）；
- 键鼠设置：Alt 切换鼠标、Ctrl 显示鼠标（P02 00:08）；
- 移动端式技能轮盘/触摸布局（P03 右下、P11 卡面）。

【推断】存在统一的 **输入抽象层**：同一套技能/交互数据，按设备映射到键位、手柄、触摸；UI 布局有安全区/缩放适配。

### 1.3 对我们的映射

- 我们客户端是 Flax（C#），PC 为主；若要跨端，需要先做输入抽象与 UI 缩放，而不是复制两套 UI。
- Messiah 的具体实现不可得；可借鉴的是“同一套数据驱动多端映射”的工程原则。

## 2. 世界与流式加载

### 2.1 可见证据

- 区域：清河、开封、河西、凉州、秦川、不见山（主视频标题/章节）；
- 地图：纸面地图 + 区域完成度 + 图层（一层/二层/三层）+ POI（P24 00:02–00:48）；
- 无缝大地图：玩家可从野外进入城镇/洞窟，无明显加载（P02、P24）；
- 双轨世界：单人/多人切换（P02 00:54、P24）；
- 天气/时辰：时辰盘（P16 00:32）、夜间灯光（P24 03:44）；
- 大量 NPC：城镇人群（P12 00:00–00:20、P16 00:00）。

### 2.2 推断

1. **分块流式加载**：大世界按区域/网格分块，靠近时加载高模/贴图，远处 LOD/Impostor；
2. **多层地图**：城市/洞窟有独立楼层数据，地图 UI 可切换楼层；
3. **双世界实例**：单人/多人不是同一份世界状态；多人世界可能是独立实例/分片，通过菜单进入；
4. **活动副本**：侠境/试剑是独立场景实例，进入时加载，退出回原世界；
5. **NPC 生态**：宣传称“上万名 NPC 实时生态计算”，实际可能是分区域/分帧调度 + 简化 AI，不是全图全量模拟。

### 2.3 对我们的映射

- 我们已有 `ZoneShardGrain`、AOI（Morton）、快照/插值；单一大世界。
- 可借鉴：
  - **副本实例管理**：`DungeonGrain` 已有骨架，需补“创建/销毁/回城/超时”生命周期；
  - **分层地图数据**：地图 UI 需要楼层概念（我们的世界地图目前是平面）；
  - **活动场景加载**：进入副本前预加载，避免切图卡顿。

## 3. 动画与角色

### 3.1 可见证据

- 角色移动/奔跑/跳跃/滑翔/攀爬/钩索（P02 01:00–02:20）；
- 战斗连招/武器切换/奇术（P03、P09）；
- 面部/口型/剧情演出（P01、P09；虽为单人内容，但技术栈共享）；
- 布料/头发/配饰摆动（P09 角色特写、P04 立绘）；
- 受击/硬直/倒地（P03、P18）。

### 3.2 推断

- 动作系统需要：动画图/混合树、上下半身分层、根运动、IK（脚部贴地/手部持械）、面部 BlendShape；
- 战斗需要：攻击判定窗口、命中停顿、受击方向、处决/处决镜头；
- 多人同步需要：动画状态同步（或只同步关键状态+客户端预测），否则 10 人本动画带宽爆炸。

### 3.3 对我们的映射

- 我们项目记忆明确：动画图/混合树/根运动是短板；角色模型/骨骼 retarget 已做过（Idle/Walk/Run/Sprint 混合）。
- 建议：
  1. 先做“移动/待机/攻击/受击/死亡”五态 + 上下半身分层；
  2. 再做武器/奇术动作；
  3. 多人同步只同步“状态 + 时间 + 朝向”，客户端本地播放，服务器校验关键判定。

## 4. 输入与相机

### 4.1 可见证据

- 键鼠：WASD、Shift 冲刺、Space 跳跃、Ctrl 下蹲、Alt 切换鼠标（P02 00:08–00:40）；
- 手柄：LB 防御、LT、RB（P03 00:30、00:52）；
- 相机：动作模式、锁定目标（P02 设置；P03 Boss 战锁定）；
- 技能轮盘：右摇杆/鼠标选择（P03 右下）。

### 4.2 推断

- **输入抽象**：ActionMap（移动/战斗/UI/菜单），按设备绑定；
- **相机**：第三人称越肩、锁定、碰撞回退、FOV 动态；
- **UI 输入隔离**：打开菜单时屏蔽世界输入（我们已有 `InkWorldInputGate` 类似机制）。

### 4.3 对我们的映射

- 我们已有第三人称相机改造方案（项目记忆 `第三人称相机魔兽世界风格改造方案`）、`InkWorldInputGate`。
- 建议补“锁定目标 + 软锁/硬锁 + 相机碰撞”，并把技能轮盘输入接到真实技能。

## 5. 网络与多人

### 5.1 可见/旁证

- 单人/多人双世界（UI）；
- 5 人/10 人副本、匹配、准备阶段、周首通（UI + 旁证）；
- PvP 多模式（旁证）；
- 世界层路牌/悬赏/据点/野外首领（UI）；
- 跨端互通（旁证）；
- 官方/渠道服划分（旁证）。

### 5.2 推断架构

```
客户端
 ├─ 单人世界（本地/半本地模拟，服务器存档）
 └─ 多人世界（服务器权威，AOI 同步）
      ├─ 大世界分片/实例
      ├─ 副本实例（5/10 人，独立场景）
      └─ PvP 对局（房间/匹配）
```

- **副本/对局是独立实例**：进入时创建/分配，退出销毁；与我们的 `DungeonGrain` 类似。
- **AOI**：10 人本不需要全图同步，只需同步队友/Boss/关键召唤物；世界层按距离/网格裁剪。
- **服务器权威**：Boss 血量/仇恨/掉落、PvP 伤害、悬赏状态必须服务器判定；客户端只做表现。
- **匹配**：按等级/战力/职责/阶段匹配；进入副本后可继续补位（旁证）。
- **跨端**：同一账号/角色数据，输入/UI 适配；网络协议一致。

### 5.3 与我们架构的对比

| 维度 | 燕云（推断） | HundunWorld |
|---|---|---|
| 世界 | 单人/多人双轨 + 活动实例 | 单一大世界 + ZoneShard/AOI |
| 同步 | 服务器权威 + 实例 | 服务器权威 + 预测/和解/插值 |
| 副本 | 独立实例，5/10 人 | DungeonGrain 骨架，未接 |
| 匹配 | 有 | 无 |
| 跨端 | PC/移动 | PC（Flax） |
| 社交 | 路牌/悬赏/帮派/交易 | 好友/聊天已接，其余骨架 |

结论：**我们的底层同步不比燕云差，差在上层玩法编排**。应把 `DungeonGrain`/`TeamGrain`/`GuildGrain`/`MarketGrain` 接到网关，而不是重写网络层。

## 6. UI 技术

### 6.1 可见证据

- 大量半透明面板、纸纹、金线、渐变、圆角/直角混合；
- 列表/网格/轮盘/地图多形态；
- 高密度文字与图标；
- 跨端布局（PC/移动）；
- 地图缩放/平移/图层（P24）；
- 背包筛选/对比（P22）。

### 6.2 推断

- UI 可能是自研 retained-mode 框架 + 数据绑定；页面按“列表-详情”复用组件；
- 文本/图标有图集/字体缓存；地图是矢量/瓦片混合；
- 大量半透明叠加对 Overdraw 有压力，移动端需要合批/降级。

### 6.3 对我们的映射

- 我们 Ink UI 是 C# retained-mode，已有 75+ 页面；问题在“每页手写布局 + 数据绑定散落”。
- 建议：
  1. 抽 `ListDetailPage`、`CardGridPage`、`FilterBar`、`CurrencyCell` 等模板；
  2. 数据绑定统一走 Binder/Service，不在页面构造函数里塞假数据；
  3. 加 UI 性能预算（Overdraw/布局次数），低端设备降级。

## 8. 安全与公平（推断）

- 悬赏/海捕需要服务器权威的犯罪记录与伤害归属，客户端不能自证；
- 10 人本掉落/周首通需要服务器记录，防止改本地时间/重放；
- PvP 需要独立数值与反作弊（速度/攻击频率/命中判定）；
- 交易需要绑定/税/日志，防止 RMT/复制。

对我们的启示：**先把权威状态放服务端，再做 UI**；UI 只读服务端回执，避免“本地改数字”的假交互（项目记忆已多次踩坑）。
