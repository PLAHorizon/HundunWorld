# 10 · 策划方法论：可复用的 10 个设计模式

> 从燕云联网内容中抽象出的“可迁移到 HundunWorld”的策划模式。每条给：机制 → 证据 → 适用条件 → 我们的落点/反模式。  
> 不包含单人剧情/关卡设计。

## 模式 1：活动分层（四类玩法 + 闯荡 + 同游聚合）

**机制**：把联网玩法收进「四类核心玩法 + 闯荡活动列表 + 同游聚合页」，每个入口对应一种社交强度：

| 入口 | 社交强度 | 内容 |
|---|---|---|
| 侠境 | 强（10 人） | 团本/周本 |
| 试剑 | 中（5 人） | 小队副本 |
| 止戈 | 对抗（1v1/多队） | PvP |
| 同游 | 聚合（本周目标） | 四卡聚合：侠境/试剑/止戈/闲趣 |
| 闯荡 | 多人活动列表 | 群力共伐/天泉特训/福地修炼/五禽戏/红炉雅集/多人会诊/悬壶济世/献艺共舞 |
| 闲趣 | 弱（可单人/组队） | 小游戏 |

**证据**：P11 01:42（顶部入口）、01:34（同游聚合）、04:10（闯荡列表）。

**适用条件**：玩法数量 ≥ 5，且玩家需要“今天玩什么”的决策入口。

**我们的落点**：`MenuActivitiesPage`/`MultiplayerPage` → “同游”聚合页；不要按系统名平铺 20 个入口。

**反模式**：所有玩法都塞进侧边栏，玩家不知道先点哪个。

---

## 模式 2：规模徽标 + 职责标签

**机制**：入口卡片直接印“10人/5人”和“缺治疗/推荐武学造诣”，把组队决策前置。

**证据**：P11 01:42/02:06（10人、缺少治疗职责、推荐造诣 40120/38000）；P06 00:20（输出近战/远程/承伤/治疗）。

**适用条件**：组队内容需要角色分工。

**我们的落点**：`DungeonEntryPage` 卡片、`MenuTeamPage` 成员槽；`RoleTag` 组件。

**反模式**：进本后才发现没治疗/人数不对。

---

## 模式 3：智能助战（AI 补位）

**机制**：10 人本允许“智能助战自动补充智能队友”，解决组队难；但 AI 不拿首通奖励（从规则推断）。

**证据**：P11 01:42 规则文本。

**适用条件**：高人数副本 + 匹配池不足。

**我们的落点**：`TeamGrain` 增加 AI 成员标记；`DungeonGrain` 允许 AI 占位；奖励结算排除 AI。

**反模式**：AI 太强导致玩家不带真人；必须限制 AI 强度/奖励。

---

## 模式 4：奖励次数共享 + 独享奖励

**机制**：同阶段每个 Boss 每周一次；不同难度共享次数；首次解锁给“独享奖励”，不计入共享；每周全通额外奖励。

**证据**：P11 01:42 规则文本。

**适用条件**：多难度/多 Boss 的周本。

**我们的落点**：`DungeonProgress` 配置：`WeeklyPerBoss`、`SharedAcrossDifficulty`、`FirstClearExclusive`、`FullClearBonus`。

**反模式**：每个难度都能领一次 → 玩家被逼着刷低难度；或首通奖励可重复领 → 经济崩。

---

## 模式 5：按来源的周上限

**机制**：通宝周上限只统计“日常可重复产出”；心力玩法/怪物掉落/一次性奖励/兑换不计入。

**证据**：P04 01:56/02:08（32,208/220,000；排除项文案）。

**适用条件**：有可重复刷的日常产出。

**我们的落点**：`CurrencyCapRule`（货币/来源/周期/上限/是否计入）；所有发奖入口统一走 `CurrencyGrantService`。

**反模式**：按货币总额封顶 → 一次性奖励也被卡；或各入口各写一套 → 有入口绕过。

---

## 模式 6：不肝商店（时间保底）

**机制**：用周限购代币兑换材料，给休闲玩家稳定保底；每格显示“周限购 40/40”。

**证据**：P11 02:28–02:30、05:12；P08 01:14。

**适用条件**：材料掉落随机、玩家有“非酋”焦虑。

**我们的落点**：`ShopHandler` 行级 `WeeklyLimit/WeeklyBought`；UI `WeeklyLimitBadge`。

**反模式**：限购不显示 → 玩家点了才知道不能买；或限购可被绕过。

---

## 模式 7：异步 UGC（路牌）

**机制**：玩家在世界放置文字/配图/动作，其他玩家可见、点赞/点踩、留言、花材料加固；可见性分层（自己/好友/帮派/所有人/关闭）。

**证据**：P12 00:10–00:38。

**适用条件**：开放世界 + 有位置概念。

**我们的落点**：`RoadSign` 实体 + AOI 查询 + 设置开关 + 敏感词/举报；先做文本，不做音乐盒。

**反模式**：只做“世界弹幕”没有位置/作者/治理；或默认所有人可见导致骚扰。

---

## 模式 8：犯罪 → 悬赏 → 抓捕（PvP 的世界理由）

**机制**：律令/犯罪记录 → 悬赏单（试炼/营生/仇杀/同游）→ 真人跨世界抓捕 → 赏金/海捕状态。

**证据**：P18 02:28–03:46。

**适用条件**：有 PvP 开关/安全区/服务器权威判定。

**我们的落点**：`CrimeRecord`/`BountyGrain`；先做“安全区不可攻击 + 1v1”，再做海捕。

**反模式**：没有犯罪记录就直接红名 → 误伤/报复/刷赏金。

---

## 模式 9：双层地图（世界 + 工作台）

**机制**：地图不只是“看”，而是“区域完成度 + 本周目标 + 图层 + POI + 快速挑战”的工作台；单人/多人是页签。

**证据**：P24 00:18–00:48；P11 04:40–04:44。

**适用条件**：开放世界 + 多区域。

**我们的落点**：`WorldMapPage`/`CompassPage` 增加区域完成度、本周目标、图层；保留 POI 真实数据。

**反模式**：地图只是静态贴图；右栏信息造假（我们已清过一轮假数据）。

---

## 模式 10：外观/便利商业化，不碰战力

**机制**：商城主要卖外观/月卡/战令；战斗材料靠玩法；不肝商店做保底；和鸣偏外观/收集。

**证据**：P11 02:52–03:02（外观/坐骑/宠物）；P11 04:04（战令/月卡）；旁证：玩家长评称“氪金不碰战斗数值”。

**适用条件**：长线运营 + 外观产能。

**我们的落点**：先做 `MenuShopPage` 外观/月卡；不要做“充值加战力”；抽卡只做外观且概率公示。

**反模式**：把周本材料放进商城 → 付费即变强，破坏我们服务器权威与公平。

## 附：需求文档模板（可直接套用）

每个联网玩法立项时，用这张表填空：

| 字段 | 说明 |
|---|---|
| 玩法名/入口 | 属于侠境/试剑/止戈/闯荡/闲趣中的哪一个 |
| 社交强度 | 单人可玩 / 建议组队 / 强制组队 / 对抗 |
| 规模 | 1/5/10 人；是否支持智能助战 |
| 时长 | 单局目标时长；是否可中断/重连 |
| 角色分工 | 输出近战/远程/承伤/治疗；是否限制治疗数量 |
| 奖励 | 首通/周常/赛季/外观；是否共享次数 |
| 上限 | 货币/材料/次数；按来源还是按总额 |
| 失败路径 | 团灭/掉线/超时/重复领奖 |
| 权威 | 哪些状态必须服务端判定 |
| UI | 入口卡/队伍框/结算页/空态 |
| 验收 | 2/5/10 客户端脚本 + 重放/并发测试 |
| 反模式 | 假交互/假数据/本地改数字 |
