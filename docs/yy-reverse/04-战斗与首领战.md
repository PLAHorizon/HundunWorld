# 04 · 战斗与首领战逆向

> 口径：只分析联网战斗（副本/团本/PvP/世界首领）；单人剧情战斗只作为操作与 HUD 的对照，不展开。  
> 证据：P=分 P，时间码=片内时间；【实证】画面可见，【旁证】公开资料互证，【推断】工程反推。

## 1. 操作与战斗资源

### 1.1 基础操作（P02 00:08–00:40）

设置页「基础设置 / 键位设置」可见：

- 镜头模式：动作模式；
- 技能显示方式：简洁；
- 键位：移动、跳跃、冲刺、闪避、**卸势**、锁定、呼出轮盘、打开任务、地图、交互；
- 鼠标：Alt 切换鼠标，Ctrl 显示鼠标；
- 攻击：轻击/重击；武学技能；奇术；防御（HUD 出现「防御 LB」提示）。

【旁证】战斗资源包括：

- **气血**：生命；
- **真气**：通用内力；
- **耐力**：武学蓝量；
- **精元**：奇术蓝量；
- **势/气竭**：架势条/破防状态（“卸势”与“气竭”是核心博弈）。

### 1.2 核心动作循环

从画面与公开资料可还原为：

```
观察敌人起手 → 闪避/走位 → 卸势（格挡/弹反）→ 敌人气竭/破防
   → 轻/重击 + 武学连招 + 奇术 → 处决/爆发
   → 资源（耐力/精元）管理 → 循环
```

设计要点：

1. **卸势是“高风险高回报”**：不是无脑按住格挡，而是时机判定；成功卸势制造气竭窗口。
2. **双资源分离**：武学吃耐力、奇术吃精元，避免“一套连招倾泻所有资源”。
3. **武器/武学切换**：多武器 + 主/副武学，允许战斗中切换流派。
4. **奇术是功能位**：点穴、狮吼、太极等提供控制/位移/破防，不是单纯伤害。

### 1.3 对我们的映射

- 我们已有 `Horizon.Game.Sim/CombatCore.cs`、`Horizon.Game.Core/Combat/AttributeDerivation.cs`、五行倍率、技能/冷却/EffectSystem。
- 缺：**卸势/气竭/处决**的服务器权威判定；**锁定**与镜头（见项目记忆的第三人称相机改造方案）；**耐力/精元**双资源；**武学切换**。
- 建议先在 PvE 做“卸势→气竭→处决”的最小闭环，再扩展到 PvP；不要先做复杂连招编排。

## 2. 属性模型

### 2.1 战斗属性页（P05 00:06–01:24）

可见字段：

- 基础：气血、真气、体、御、敏、势；
- 攻击：外功攻击 1551–2872、属性攻击 358–1021；
- 防御：外功防御、内功防御、属性抗性；
- 命中/暴击：精准率 126.4%、会心率 96.6%、会意率 39.0%、直接会心、会心伤害；
- 气血上限 16,609 / 19,928，真气上限 100；
- 五行：金/木/水/火/土（武学/奇术/装备词条）。

### 2.2 设计要点

1. **双轨攻击**：外功攻击 + 属性攻击，分别对应物理与五行；属性攻击受五行克制影响。
2. **三层命中体系**：精准（命中）、会心（暴击）、会意（额外连击/特殊效果）——比传统“命中/暴击”多一层，提供词条深度。
3. **防御分内外功 + 属性抗性**：避免单一“防御”数值通吃。
4. **数值可见**：百分比与绝对值并列，方便玩家比较装备。

### 2.3 对我们的映射

- 我们已有 `AttributeDerivation` 与五行倍率；缺“会意/精准”等二级属性、属性抗性、装备词条聚合（见项目记忆：装备加成未进服务端结算）。
- 建议先把 **装备词条 → AttributeDerivation** 接上，再做二级属性；否则 UI 上的词条只是展示。

## 3. HUD：信息层级与战斗可读性

### 3.1 画面元素（P03、P05、P09、P11、P18）

以 P03 01:20–01:50 的 Boss 战为例：

```
┌────────────────────────────────────────────────────────────┐
│ 小地图+任务追踪(左上)           Boss 血条+名称+计时(上中)    │
│                                                            │
│                                        系统入口图标(右上)   │
│                                                            │
│                                        目标锁定/距离(右中)  │
│ 聊天/状态(左下)                                            │
│              玩家气血/真气条(下中)                          │
│                         技能轮盘+4向技能(右下)  交互提示(F) │
└────────────────────────────────────────────────────────────┘
```

逐项：

| 元素 | 位置 | 作用 | 证据 |
|---|---|---|---|
| 小地图 + 罗盘 | 左上/上中 | 方向、POI、任务目标 | P02、P03、P24 |
| 任务追踪 | 左上（小地图下） | 当前目标/距离（“带领伊刀进入暗道 8米”） | P03 00:30 |
| Boss 血条 | 上中 | 名称、血量、计时（03:22） | P03 01:20–01:50 |
| 玩家气血/真气 | 下中 | 生命/内力 | P03 00:30 |
| 技能轮盘 | 右下 | 普攻/武学/奇术/闪避/卸势 | P03 00:30、P09 |
| 交互提示 | 目标附近/右下 | F 交互、防御 LB | P03 00:30、P03 01:20 |
| 伤害数字 | 世界空间 | 即时反馈（498、1932、6407、12,349） | P03 01:44；P25 00:24；P18 03:06 |
| 系统入口 | 右上 | 菜单/背包/地图/社交等 | 多画面 |
| 聊天 | 左下 | 频道/输入 | P02、P03 |

### 3.2 设计要点

1. **上中 Boss 条 + 计时**：把“还有多久/打到哪”放在视线中心，减少低头看 UI。
2. **下中只有两条**：气血/真气，不做过多资源条；耐力/精元通过技能图标/环形提示表达。
3. **右下技能轮盘**：围绕一个圆心排布，符合手柄/鼠标手势；PC 显示 LB/LT 键位。
4. **交互提示就近**：不占用固定 HUD 区域，减少视觉噪音。
5. **伤害数字分层**：普通伤害白/黄，暴击/会意更大字号/不同颜色；Boss 伤害数字在目标上方。

### 3.3 对我们的映射

- 我们已有 `CombatHudTraditionalPage`、`CombatHudV2Page`、`ControlStateChipView`、`InkMinimap`。
- 缺：Boss 血条/计时/阶段、目标锁定框、伤害数字分层、技能轮盘的真实技能绑定（见项目记忆：V2 底部 8 格 mock）。
- 建议把 HUD 拆成“常驻层（小地图/任务/血条）+ 上下文层（Boss/交互/目标）+ 瞬时层（伤害/提示）”，每层独立更新，避免整页重排。

## 4. Boss 与团本设计

### 4.1 画面证据

- P03 01:20–01:50：Boss「无相皇·阴啸」，上中血条 + 计时 03:22；玩家使用剑/奇术；伤害数字 498/1932；场景为洞窟/石台。
- P11 01:42：侠境页「夹钟奏雅·上」，Boss 立绘「白裘殁天狼」，右上角「10人」；右侧规则含「智能助战」「奖励次数共享」「独享奖励」。
- P11 02:06：Boss 卡片「白裘殁天狼」，10人、智能助战/团队、推荐武学造诣 40120/38000、本周首领奖励、专属外观、缺少治疗职责。
- P11 02:16：另一 Boss「玉魄染青苍」。
- P11 04:10：「群力共伐」帮派/群体战页（每周 2 次奖励）。
- P16 04:12–05:44：武林录的「据点 / 野外首领」分类页（**未证明必须多人**，见 02 报告第 7 节）。

### 4.2 设计要点

1. **Boss 即内容单元**：一个 Boss 卡片承载难度、人数、奖励、外观、周次数；玩家在入口就能判断“值不值得打”。
2. **周轮换**：本周首领/本周奖励，避免同一 Boss 刷到腻。
3. **协助/补位**：10 人本允许助战，解决组队难。
4. **多难度**：挑战模式；配合角色定位推荐。
5. **专属外观**：Boss 掉落外观，提供非数值追求。

### 4.3 对我们的映射

- 我们有 `MonsterEditor`、`MonsterAiCore`、`CombatGrain`、`DungeonGrain`；缺 Boss 阶段/词条/仇恨/贡献/周首通。
- 建议先在 `DungeonGrain` 上做“副本模板 + Boss 阶段 + 词条”配置，再接 `TeamGrain` 与结算；10 人本优先做“共享 Boss 血量 + 伤害贡献排名 + 周首通”。

## 5. PvP 战斗（止戈）

### 5.1 画面与旁证

- P11 01:42 顶部一级导航出现「止戈」；具体模式/积分以旁证为准（本视频未打开止戈详情页）。
- 旁证：论剑 1v1、觉障林吃鸡、争锋/演武/天下争鸣；准备阶段禁用技能/奇术、射箭初始精元 40%、战斗中精元恢复 +20%；天下争鸣准备场景可切换武学，治疗职责 ≤1。

### 5.2 设计要点

1. **准备阶段与战斗阶段分离**：准备阶段禁用技能，避免开局偷袭。
2. **资源初始值调整**：PvP 中精元初始 40%、恢复 +20%，改变节奏。
3. **职责限制**：治疗 ≤1，防止阵容失衡。
4. **多模式**：1v1 硬核、吃鸡低门槛、多队阵营。

### 5.3 对我们的映射

- 我们目前没有 PvP 规则；`Arena` 目录存在但未验证。
- 建议先做 1v1 房间（复用 CombatGrain），再做吃鸡；PvP 数值必须与 PvE 分离（独立倍率/资源），否则平衡会被 PvE 装备破坏。

## 6. 战斗表现与技术

### 6.1 可见表现

- 武器拖尾/刀光（P03 01:20 白色弧光）；
- 命中停顿/震屏（【推断】从画面节奏判断）；
- 伤害数字（白/黄/大字号）；
- Boss 受击硬直/气竭（【推断】）；
- 场景破坏/尘雾（P03 01:36 尘雾）；
- 轻功/位移（P02 01:00 跳跃/滑翔）；
- 天气/时辰（P16 00:32 时辰盘）。

### 6.2 技术推断

- 动作系统需要 **动画图/混合树 + 根运动 + IK**；燕云的角色在移动/攻击/受击间过渡自然，推测使用了动作匹配或高质量混合。
- 命中判定需要 **服务器权威 + 客户端预测**；多人副本中 Boss 血量/仇恨必须服务器权威。
- 10 人本需要 **AOI/同步裁剪**：只同步附近玩家与 Boss，远程玩家做低频更新。
- 跨平台（PC/移动）需要 **输入抽象 + 技能轮盘自适应**（PC 显示 LB/LT，移动显示触摸按钮）。

### 6.3 对我们的映射

- 我们客户端 Flax 的动画图/混合树仍是短板（项目记忆：动画空图史、根运动缺失）。
- 建议先做“移动/待机/攻击/受击/死亡”五态混合，再做卸势/处决；不要一开始做全动作匹配。
- 网络层已有预测/和解/插值；副本内需要新增“Boss 权威 + 伤害贡献”消息。
