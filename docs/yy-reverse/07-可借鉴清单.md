# 07 · 可借鉴清单（按优先级）

> 原则：**只借鉴联网/开放世界内容**；单人剧情、残章、奇遇、单人解谜不列入。  
> 每条给出：证据 → 我们的现状（文件级）→ 借鉴方式 → 工作量/风险 → 验收。  
> 工作量以“1 名熟悉本仓库的工程师”为基准，含客户端+服务端+测试，不含美术。

## 0. 先给结论：最值得抄的 5 件事

| 排名 | 借鉴项 | 为什么 | 我们的最大障碍 |
|---|---|---|---|
| 1 | **同游活动中心**（侠境/试剑/止戈/闲趣四卡 + 闯荡多人列表） | 把“今天玩什么”压成一屏，极大降低组队决策成本 | 我们的活动页是系统列表，不是“本周目标” |
| 2 | **5/10 人副本 + 组队/匹配 + 周首通** | MMO 的留存骨架；燕云用 5/10 人做出社交梯度 | `SocialHandler` 的 Team 分支是假成功桩；匹配不存在 |
| 3 | **路牌（异步 UGC）** | 投入最小、在场感最强；不需要实时同屏 | 缺世界留言实体/审核/可见性设置 |
| 4 | **周上限 + 不肝商店** | 防刷、防通胀、给休闲玩家保底 | `CurrencyGrain` 只有余额，无按来源周期上限 |
| 5 | **Boss HUD + 卸势/气竭/处决** | 战斗可读性与操作深度 | 无 Boss 条/锁定/卸势判定；动画图薄弱 |

## 1. P0：不做会卡住联网闭环

### P0-1 同游活动中心（UI 先行）

**证据**：P11 01:34、01:42、04:16、04:24。

**现状**：
- `HundunWorld/Source/Game/UI/Ink/Pages/Activities/MenuActivitiesPage.cs`：样例数据；
- `Multiplayer/MultiplayerPage.cs:461`：“大厅服务尚未开放”；
- `MenuTeamPage.cs:410`：“组队功能未接入”；
- `Dungeon/DungeonEntryPage.cs:472`：“秘境副本尚未接入”。

**借鉴方式**：
1. 把 `MenuActivitiesPage` 改成「同游」聚合页：
   - 顶部：本周目标（首通/周上限/赛季进度）；
   - 卡片：侠境（10人）、试剑（5人）、止戈（PvP）、闲趣；另设「闯荡」多人活动列表与百业入口；
   - 每卡：人数徽标、本周奖励、剩余次数、主按钮。
2. 数据先走本地配置（`ActivityCatalog`），服务端就绪后切真数据；**不允许假交互**（按钮未接就禁用/提示）。
3. 与 `InkPageRouter` 的 `nav-multiplayer`/`nav-activities`/`nav-team`/`nav-dungeon-entry` 统一入口。

**工作量**：6–8 人日（纯 UI + 配置）。  
**风险**：低；主要是布局/溢出（项目记忆有 StretchAll 溢出批检）。  
**验收**：
- 40 页回归不新增 BLANK/溢出；
- 每张卡片的数据来自配置，不写死；
- 未接服务端的按钮 `Enabled=false` 或弹“尚未接入”。

### P0-2 组队服务：把假桩换成 TeamGrain

**证据**：P11 01:42/02:06（10人、缺少治疗职责、推荐造诣 40120/38000）；P06 00:20（职责定位）。

**现状（关键缺陷）**：
- `Horizon.Game.Core/Handlers/SocialHandler.cs:103` 的 `HandleTeamAsync` 直接返回 `Success=true` 和空 `TeamInfo`，**没有调用 `TeamGrain`**；
- `SocialHandler.cs:125` 的 `HandleGuildAsync` 同样是假成功；
- `Horizon.Orleans.Grains/TeamGrain.cs` 已有 Create/Join/Leave/Kick/Transfer/EnterDungeon 等完整实现；
- 客户端 `MenuTeamPage` 仍是设计稿。

**借鉴方式**：
1. 新增/替换 `TeamHandler`（或改 `SocialHandler` 的 Team 分支）：
   - `CreateTeamRequest` → `TeamGrain.CreateTeamAsync`；
   - `JoinTeamRequest` → `JoinTeamAsync`；
   - `Leave/Kick/Transfer/Disband` 对应；
   - 回执带真实 `TeamInfo`/`Members`，失败带原因码。
2. 消息契约：在 `Horizon.Game.Message/Network/` 增加/补齐 Team DTO（MemoryPack + `[NetworkMessage]`）。
3. 客户端新增 `TeamClientService`，`MenuTeamPage` 绑定；HUD 队伍框订阅。
4. 职责/准备：队伍成员带 `Role`（输出近战/远程/承伤/治疗）与 `Ready`。

**工作量**：10–14 人日（服务端 6 + 客户端 4 + 测试 2）。  
**风险**：中；TeamGrain 的并发/领导权切换/断线重连要测。  
**验收**：
- 两个客户端可创建/加入/离开同一队伍；
- 成员列表与服务器一致（改名/离线/队长转移）；
- 断线重连后队伍状态恢复；
- `TeamGrain` 单测 + 网关集成测试覆盖每个失败分支。

### P0-3 5/10 人副本与周首通

**证据**：P11 01:42–02:16（侠境 10人/规则）、P11 01:42 顶部试剑入口、P11 01:34 同游 + 旁证（5人本/周首通/心力）。

**现状**：
- `Horizon.Orleans.Grains/DungeonGrain.cs` 有 CreateDungeon/Players/Bosses；
- `TeamGrain.EnterDungeonAsTeamAsync` 可把队伍带进副本；
- `DungeonEntryPage` 未接服务端；
- 无周首通记录、无匹配、无心力。

**借鉴方式**：
1. 副本模板配置：`DungeonTemplate`（人数 5/10、难度、Boss 列表、周奖励、首通奖励、时间限制）。
2. `DungeonGrain` 生命周期：创建 → 加入 → 开始 → 结算 → 销毁/超时。
3. 周首通：`DungeonProgressGrain` 或 `CharacterGrain` 字段（角色/周/Boss/是否首通）。
4. 匹配：先做“队伍招募板”（列出队伍），再做自动匹配；不要一开始做复杂 MMR。
5. **智能助战**：P11 01:42 明确“智能助战会自动补充智能队友”。可在匹配不足时用 AI 队友补位（Boss 战可用简化 AI），解决 10 人本组队难；AI 队友不能拿首通奖励，避免刷。
6. **奖励次数规则**：同阶段每个首领每周一次、不同难度共享次数、每周全通额外奖励、首次解锁“独享奖励”不计入共享——这套规则可直接作为我们 `DungeonProgress` 的配置模板。
7. 结算：Boss 伤害贡献、掉落分配（需求/贪婪/队长分配先做一种）。

**工作量**：15–20 人日（服务端 8 + 客户端 5 + 测试 3 + 配置 2）。  
**风险**：高；副本生命周期/掉落/断线重连/重复领奖是常见坑。  
**验收**：
- 5 人/10 人队伍可进入同一副本，看到彼此与 Boss；
- Boss 血量/阶段/伤害贡献服务器权威；
- 每周首通只发一次（跨周重置、重放不重复）；
- 退出/掉线/团灭/超时都能正确销毁实例。

### P0-4 周上限 + 不肝商店

**证据**：P04 02:08（通宝 220,000/周，来源分类）；P11 02:30、05:12（周限购 40/40）；P11 04:04（战令周经验 18,000）；P11 03:52（和鸣周上限 2,000）。

**现状**：
- `CurrencyGrain` 有余额，无周期上限；
- `ShopHandler` 有买卖，无周限购；
- `MenuShopPage` 已接部分真数据，但无“本周已用/上限”。

**借鉴方式**：
1. 新增 `CurrencyCapRule`（货币/来源/周期/上限/是否计入），配置化；
2. 所有发奖入口（任务/副本/世界事件/商店）统一走 `CurrencyGrantService` 校验并回执 `granted/used/cap`；
3. 商店行增加 `WeeklyLimit`/`WeeklyBought`，服务端校验；
4. UI 显示“本周 32,208 / 220,000”“周限购 40/40”。

**工作量**：8–10 人日。  
**风险**：中；来源分类必须统一，否则会出现“某个入口绕过上限”。  
**验收**：
- 同一货币不同来源分别计数；
- 一次性奖励/掉落不计入；
- 超限时回执 `granted=0`、原因明确；
- UI 三元组随发奖刷新。

### P0-5 路牌：异步社交 UGC

**证据**：P12 00:00–00:38（路牌与世界、设置页可见性开关）。

**现状**：
- 有世界坐标、POI、聊天、数据库；
- 无世界留言实体/查询/审核。

**借鉴方式**：
1. 服务端 `RoadSignGrain` 或表：`Id/CharacterId/Position/Text/Media/Visibility/CreatedAt/ExpiresAt/ReportCount/GoodCount/BadCount/ReinforceLevel`。
2. 客户端：AOI 内按距离查询（例如 30 米），世界标记 + 交互面板；放置时输入文本/配图/选择可见性；面板显示作者、赞/踩、评论、加固按钮。
3. 可见性：自己/好友/帮派/所有人/关闭；设置页复用现有开关组。
4. 互动：好人/坏人评价、留言、重播动作、**花材料加固**（轻量 sink，延长路牌寿命/提升可见度）。
5. 审核：敏感词过滤 + 举报 + 隐藏；先做“文本+开关”，不做音乐盒。

**工作量**：8–12 人日（服务端 4 + 客户端 4 + 审核 2 + 测试 2）。  
**风险**：中；UGC 审核/刷屏/坐标泄漏。  
**验收**：
- A 放置路牌，B 在范围内可见；关闭“其他玩家路牌”后不可见；
- 路牌不随玩家下线消失（持久化）；
- 举报后隐藏；敏感词拦截；
- 路牌不参与战斗/不被误选为目标。

## 4. 不建议照搬的部分

| 项 | 原因 |
|---|---|
| **双轨世界（单人/多人切换）** | 我们是单一大世界 + 服务器权威；复制会撕裂 AOI/社交/经济 |
| **单人模式等级** | 单人内容不在本次范围；若做剧情模式，应独立数值档，而不是复制世界 |
| **和鸣抽卡（若含战力）** | 破坏公平；只可做外观，且需概率公示/合规 |
| **过度密集的 10–12px 小字** | 720p 可读性差；我们应提高对比度/字号 |
| **四层以上的菜单嵌套** | 新手迷路；我们用面包屑/最近访问/一句话解释 |
| **侠迹/残章/奇遇等单人内容节奏** | 与联网无关，不纳入 |

## 5. 借鉴时的反模式（来自我们项目历史）

1. **假交互**：点了本地改数字/只冒金光/静默跳回——一律按未接线处理（项目记忆多次踩坑）。
2. **假数据**：设计稿数值必须清零或标注“未接入”；空态逐字段清。
3. **StretchAll 溢出**：新卡片/标签必须跑 ui_tree 溢出批检。
4. **面板子控件 (0,0)**：所有新页面必须 `ApplyLayout`，不能只 `AddChild`。
5. **周上限绕过**：所有发奖入口统一走一个 `CurrencyGrantService`，不能各写各的。
6. **在客户端做权威**：副本掉落/周首通/悬赏/交易必须服务端判定。

## 6. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 范围过大（5/10人+匹配+交易+帮派一起做） | 延迟/质量下降 | 按 P0→P1→P2 切片，每片可独立验收 |
| 服务端权威缺口 | 刷奖励/复制/改本地时间 | 所有结算服务端；回执幂等键 |
| 副本断线重连 | 玩家卡在副本/重复领奖 | 实例生命周期 + 重连恢复 + 幂等结算 |
| 经济通胀 | 材料/货币贬值 | 周上限/限购/税/回收 |
| UGC 审核 | 违规内容/骚扰 | 敏感词+举报+可见性开关 |
| 动画/表现短板 | 战斗手感差 | 先五态混合，再做卸势/处决 |
| UI 溢出/可读性 | 新页面难用 | 模板化 + 自动布局 + 截图回归 |

## 7. 总体验收指标（建议）

- **功能**：两客户端可组队→进 5 人本→击杀 Boss→周首通只发一次→退出回世界。
- **经济**：同一货币不同来源分别计数；超限回执 `granted=0`；不肝商店周限购生效。
- **社交**：路牌 A 放 B 见；关闭可见性后不见；举报后隐藏。
- **性能**：10 人本同屏 60fps（目标机）；AOI 消息量在预算内。
- **UI**：40 页回归无新增 BLANK/溢出；所有未接按钮禁用/提示。
- **测试**：Gateway.Tests 新增用例覆盖每个失败分支；全量回归通过。
