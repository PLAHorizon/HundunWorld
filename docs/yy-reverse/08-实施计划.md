# 08 · 实施计划：从“页面骨架”到“联网闭环”

> 目标：把《燕云十六声》可借鉴的联网能力，按 **可独立验收的切片** 落进 HundunWorld。  
> 前提：我们已有服务端权威同步（Orleans + DS）、AOI、聊天/好友/商店/背包/技能，以及 75+ Ink 页面；缺的是**联网玩法编排**与**服务端权威数据**。

> **UI 重铸前置门**：执行 UI 重铸前，先按 [11-复核：宏观-微观对账](11-复核：宏观-微观对账.md) §7 冻结“已证”清单；7.2 的待验证项只能做占位/开关，不得写死规则。

## 0. 交付定义（Definition of Done）

每个切片必须同时满足：

1. **服务端权威**：状态在 Grain/DB，客户端只读回执；重复请求幂等。
2. **失败路径有回执**：拒绝原因码 + 可读文案；UI 不假成功。
3. **UI 无假数据**：未接字段显示 `—`/“未接入”，不写设计稿数字。
4. **自动化测试**：`Horizon.Game.Gateway.Tests` 覆盖成功/失败/重放/并发。
5. **客户端取证**：Flax PIE 截图/`ui_tree`/页面审计；40 页回归不新增 BLANK/溢出。
6. **文档**：协议、配置、回退方式、已知限制。

## 3. P0-B（W2–W4）：5 人副本闭环

### 3.1 数据与协议

| 任务 | 文件 | 说明 |
|---|---|---|
| `DungeonTemplate` | 新配置表/JSON | Id/Name/人数/难度/Boss 列表/时间限制/周奖励/首通奖励 |
| 副本生命周期 | `Horizon.Orleans.Grains/DungeonGrain.cs` | Create/Join/Start/Complete/Dispose；超时回收 |
| 队伍进本 | `TeamGrain.EnterDungeonAsTeamAsync` | 校验队长/人数/等级；返回实例 Id |
| 副本 Handler | `Horizon.Game.Core/Handlers/DungeonHandler.cs`（新增） | 入口/匹配/开始/结算/退出 |
| 周首通 | `DungeonProgressGrain` 或 `CharacterGrain` | 角色/周/Boss/首通；幂等键 |
| 伤害贡献 | `CombatGrain`/`DungeonGrain` | 记录每个玩家对 Boss 的伤害；结算排序 |
| 掉落分配 | `DungeonGrain` | 先做“个人掉落 + 队长分配”二选一 |

### 3.2 客户端

- `DungeonEntryPage`：副本列表/难度/人数/周首通状态/进入按钮。
- 副本 HUD：Boss 血条/计时/阶段、队友血条、伤害贡献、结算页。
- 匹配：先做“招募板”（队伍列表 + 申请），自动匹配后置。

### 3.3 验收

1. 5 个客户端组队 → 进入同一副本 → 看到彼此与 Boss。
2. Boss 血量/阶段/伤害贡献服务器权威；客户端不能改。
3. 通关结算：个人掉落/金币/经验；周首通只发一次；跨周重置。
4. 异常：团灭/掉线/超时/队长退出 → 实例正确销毁，不重复领奖。
5. 性能：5 人同屏 60fps；AOI 消息量在预算内。

**工期**：15–20 人日；**风险**：副本生命周期/幂等结算/断线重连。

## 4. P0-C（W5–W6）：10 人团本 + 经济闸门

### 4.1 10 人团本

- `DungeonTemplate.MaxPlayers=10`；Boss 阶段/词条/本周轮换。
- 团队框架：2 队×5 人，队长/职责/准备。

## 6. P1-B（W9–W10）：悬赏 + 市场

### 6.1 悬赏/海捕

- 犯罪记录：攻击 NPC/玩家/偷窃 → `CrimeRecord`（服务器判定）。
- 悬赏单：金额/期限/目标/发布者；`BountyGrain`。
- 击杀/抓捕 → 赏金结算；被悬赏者 HUD 红色状态。
- 安全区/ PvP 开关：先做“安全区不可攻击”，再做红名。

**验收**：A 犯罪 → B 接悬赏 → 击杀 A → B 得赏金；A 状态清除；重复结算幂等。

### 6.2 市场

- 只读：`MarketGrain.SearchListings` → 客户端列表/搜索。
- 购买：扣款/扣货/入包/税；失败补偿。
- 我的挂单/下架；公示期最后做。

**验收**：挂单→搜索→购买→入包；余额/库存一致；并发购买只有一人成功。

## 10. 决策点（需要拍板）

1. **副本人数**：先做 5 人还是直接 10 人？建议先 5 人（验证链路），再 10 人（复用模板）。
2. **掉落分配**：个人掉落 vs 队长分配？建议先个人掉落（简单、无纠纷），再做队长分配。
3. **PvP 范围**：先 1v1 还是直接阵营战？建议先 1v1（复用 CombatGrain），吃鸡/阵营后置。
4. **路牌审核**：先敏感词+举报，还是先只对好友/帮派可见？建议先“好友/帮派可见 + 敏感词”，再开放所有人。
5. **交易**：先 NPC 商店还是玩家市场？建议先 NPC 商店（已有 ShopHandler），再做市场。
6. **帮派**：先 GuildGrain 接线，还是先百业团本？建议先接线（创建/加入/成员），团本后置。
