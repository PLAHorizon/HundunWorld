## 一、结论摘要

HundunWorld 采用**完全自研**的网络同步体系，**不使用 Flax 内建 High-Level Networking**。技术栈为：

| 层 | 技术 | 版本 | 用途 |
|---|---|---|---|
| 客户端引擎 | Flax Engine | 1.12 | 渲染、物理、输入 |
| 客户端 ECS | Arch + Arch.System | 2.0.0-beta / 1.1.0 | 网络同步逻辑 |
| 网络传输 | TouchSocket | 4.1.1 | TCP 网关 |
| 序列化 | MemoryPack | 1.21.4 | 二进制序列化 |
| 压缩 | K4os.Compression.LZ4 | 1.3.8 | 快照压缩 |
| 服务端框架 | Microsoft Orleans | 10.0.1 | Actor 集群 |
| 运行时 | .NET | 10.0 | 全栈统一 |

**Netcode 模型**：客户端预测（Client Prediction）+ 服务端权威（Server Authority）+ 快照插值（Snapshot Interpolation）

**核心能力**：
- ✅ 客户端预测 + 服务端校验 + 回滚修正（Phase C1）
- ✅ 可观测性指标 + 冗余重传（Phase C2）
- ✅ 增量快照编码（Phase C3）
- ✅ 场景对象交互同步（Phase C4）
- ✅ 断线重连增量恢复（Phase C5）
- ✅ 快照消费溢出保护（Phase C6）
- ✅ AOI 兴趣集（5 chunks 半径，80m 视距）
- ✅ 协议版本 v5（10 种包类型）

## 二、架构总览

### 2.1 层级架构

```
┌─────────────────────────────────────────────────────────────┐
│  客户端 (Flax Engine 1.12)                                   │
│  ├─ Arch ECS 同步层（7 个系统）                              │
│  │   NetworkReceive → FixedUpdate → Update → Render → NetworkSend │
│  ├─ TouchSocket TCP 客户端                                   │
│  ├─ ClientSyncMetrics 可观测性                               │
│  └─ InputHistoryBuffer（回滚重播）                           │
└──────────────────────────┬──────────────────────────────────┘
                           │ TCP 7789
                           │ 帧格式: [6B 头][MemoryPack][LZ4>256B]
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Gateway (Horizon.Game.Gateway)                              │
│  ├─ TouchSocket 监听 (TcpService, 0.0.0.0:7789)             │
│  ├─ SyncPacketHandler（帧编解码 + 路由）                     │
│  ├─ GatewaySyncDispatcher（AOI fanout 分发）                 │
│  ├─ ISessionRegistry（会话→端点映射）                        │
│  └─ CharacterFingerprintService（Redis 防多开）              │
└──────────────────────────┬──────────────────────────────────┘
                           │ Orleans Client（Grain 调用 + Observer 推送）
                           ▼
┌─────────────────────────────────────────────────────────────┐
│  Orleans Silo 集群                                           │
│  ├─ ZoneShardGrain（空间权威模拟，60Hz TickAsync）           │
│  │   ├─ MovementValidator（权威移动回放 + 反作弊）           │
│  │   ├─ ZoneShardAoi（Chunk→Session 映射）                  │
│  │   └─ BroadcastSnapshotAsync（增量/全量快照广播）          │
│  ├─ PlayerSessionGrain（会话生命周期 / 重连决策）            │
│  └─ CharacterGrain（RPG 持久态）                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 数据流时序

```
玩家按键
   │
   ▼
LocalSimulationSystem（本地预测，FixedUpdate order:10）
   │  写入 PredictedTransformComponent + InputHistoryBuffer
   ▼
InputSendSystem（打包+入队，NetworkSend order:0）
   │  InputPacket{ ClientTick, InputBits, MoveX/Y, LookYaw/Pitch, CharacterId }
   ▼
TCP 上行 → Gateway → ZoneShardGrain.SubmitInputAsync()
   │
   ▼
TickAsync（60Hz）→ MovementValidator.Validate()
   │
   ├─ drift ≤ 0.5m → InputAck 确认 → 客户端清理已确认输入
   │
   └─ drift > 0.5m → CorrectionPacket 下行
                       → ReconciliationSystem（吸附+重放）
   │
   ▼
EntityDelta 广播（按 chunk AOI 过滤）
   → SnapshotApplySystem（远程实体更新）
   → InterpolationSystem（渲染插值平滑）
```

## 三、协议规范（v5）

### 3.1 帧格式

```
偏移      长度    字段              说明
[0..1]    1B      Kind              包种类（fast-path 路由）
[1..2]    1B      Compression       压缩标记（0=none, 1=LZ4）
[2..6]    4B      PayloadLength     payload 字节数（i32, 小端序）
[6..]     N B     Payload           MemoryPack 序列化字节
```

| 常量 | 值 | 说明 |
|------|-----|------|
| FrameHeaderSize | 6 | 帧头固定长度 |
| SnapshotCompressionThreshold | 256 | 超此字节启用 LZ4 |
| MaxDecompressedSize | 4 MB | 解压上限（防解压炸弹） |

### 3.2 包类型表

| Kind | 名称 | 方向 | 用途 |
|------|------|------|------|
| 1 | Handshake | C→S | 握手：协议版本 + 角色身份 |
| 2 | Snapshot | S→C | 快照：全量/增量实体状态 |
| 3 | Input | C→S | 输入：60Hz 定频上行 |
| 4 | Event | S→C | 离散事件：技能/伤害/死亡/特效 |
| 5 | WorldChunkDiff | S→C | 世界 voxel/prefab diff 流 |
| 6 | WorldPatchManifest | S→C | 世界补丁清单/版本协商 |
| 7 | InputAck | S→C | 输入确认（reconciliation） |
| 8 | ReconnectResume | C→S | 断线重连 resume 握手 |
| 9 | InteractionSync | 双向 | 交互槽状态同步 |
| 10 | SceneObjectSync | S→C | 场景对象状态同步 |

### 3.3 关键包字段

**InputPacket（Kind=3）**：
```csharp
[MemoryPackable]
public partial class InputPacket
{
    public long ClientTick;      // 客户端 tick 序号
    public uint InputBits;       // 位掩码（bit0=跳跃, bit3=轻功）
    public float LookYaw;        // 视角 Yaw
    public float LookPitch;      // 视角 Pitch
    public float MoveX, MoveY;   // 移动输入 (-1..1)
    public ulong CharacterId;    // v4 新增：角色 ID
}
```

**SnapshotPacket（Kind=2）**：
```csharp
[MemoryPackable]
public partial class SnapshotPacket
{
    public long ServerTick;      // 服务器 tick
    public long BaselineTick;    // 0=全量; 非0=增量基线
    public EntityDelta[] Deltas; // 实体变更列表
}

public struct EntityDelta
{
    public ulong EntityId;
    public EntityDeltaKind Kind;  // Spawn=1 / Update=2 / Despawn=3
    public AuthTransformComponent? Transform;
    public EntityStateAuthComponent? State;
}
```

## 四、客户端 ECS 系统

### 4.1 系统执行顺序

| 组 | 顺序 | 系统 | 职责 |
|---|---|---|---|
| NetworkReceive | 10 | SnapshotApplySystem | 消费快照，创建/更新/销毁实体 |
| NetworkReceive | 20 | InteractionApplySystem | 应用交互状态 |
| FixedUpdate | 10 | LocalSimulationSystem | 本地玩家预测 |
| FixedUpdate | 20 | ReconciliationSystem | 回滚修正 |
| Update | — | 游戏逻辑系统 | 技能、AI 等 |
| Render | 0 | InterpolationSystem | 远程实体插值 |
| Render | 10 | FlaxActorSyncSystem | ECS→Flax Actor 同步 |
| NetworkSend | 0 | InputSendSystem | 输入打包发送 |

### 4.2 本地预测（LocalSimulationSystem）

```csharp
// FixedUpdate order:10
// 查询：[PlayerInputComponent + NetworkIdentityComponent(IsLocalPlayer) + PredictedTransformComponent]
// 1. CurrentClientTick++
// 2. MovementFormula.Step() 推进 PredictedTransformComponent
// 3. 写入 InputHistoryBuffer（供回滚重播）
```

**关键约束**：
- 固定时间步 `1/60s`，与服务端 `MovementValidator.Options.TickDtSeconds` 严格对齐
- 通过 `NetworkIdentityComponent.IsLocalPlayer` 判定本地玩家
- 120 帧地面锁定保护期（防场景未加载时 RayCast miss）

### 4.3 输入发送（InputSendSystem）

```csharp
// NetworkSend order:0
// 1. 打包 InputPacket
// 2. 入队 InputSendQueue（网络层批量消费）
// 3. 写入 InputHistoryBuffer（环形缓冲，容量 64）
// 4. 冗余重传：落后 5 tick 未 ACK 则重发
```

### 4.4 回滚修正（ReconciliationSystem）

```csharp
// FixedUpdate order:20
// InputAck 处理：
//   读取 LastProcessedClientTick → 清理已确认输入
// Correction 处理：
//   drift > 0.5m → 吸附到权威位置 → 从 InputHistoryBuffer 重放未确认输入
//   drift ≤ 0.5m → 忽略（避免微抖）
```

### 4.5 快照应用（SnapshotApplySystem）

```csharp
// NetworkReceive order:10
// Spawn：创建 Arch 实体 + NetworkIdentityComponent + AuthTransformComponent
//        远程实体 → InterpolatedTransformComponent
//        本地玩家 → PlayerInputComponent + PredictedTransformComponent
// Update：刷新 AuthTransformComponent（本地玩家跳过）
// Despawn：销毁 Arch 实体
// 溢出保护：单帧消费上限（Phase C6）
```

### 4.6 插值平滑（InterpolationSystem）

```csharp
// Render order:0
// Alpha += dt * InterpolationSpeed（默认 10/s，~100ms 追平）
// pos = Start + (Target - Start) * Alpha
// 本地玩家不参与插值
```

## 五、服务端权威

### 5.1 ZoneShardGrain（60Hz Tick）

```csharp
// RegisterTimer(1/60s) → TickAsync()
// 1. 遍历 _simulatedEntities
// 2. 对有 PendingInputs 的实体调用 MovementValidator.Validate()
// 3. 生成 EntityDelta（Spawn/Update/Despawn）
// 4. 增量编码：BuildDeltaSnapshot（60 tick 周期全量）
// 5. 按 chunk AOI 过滤 → BroadcastSnapshotAsync → Fanout Observer
```

### 5.2 MovementValidator（反作弊）

| 校验维度 | 阈值 | 触发原因 |
|----------|------|----------|
| 预测漂移 | PositionEpsilon = 0.5m | PredictionDrift |
| 硬性速度上限 | HardSpeedCap = 20 m/s | SpeedHackSuspected |
| 跳跃次数 | 普通 1 次 / 轻功 3 次 | JumpCountExceeded |
| 碰撞穿越 | （预留） | CollisionOverride |

**校验流程**：
1. 从权威起点出发，按 ClientTick 升序回放输入序列
2. 逐 tick 调用 `MovementFormula.Step()`
3. 比对客户端自报终点与权威终点
4. 任一条件命中 → 生成 CorrectionPacket

### 5.3 增量快照编码

```
全量快照：每 60 tick（1s）一次，BaselineTick = 0
增量快照：BaselineTick ≠ 0，仅含变化字段
压缩：payload > 256B 时启用 LZ4
```

## 六、AOI 兴趣集

### 6.1 当前配置

```
MetresPerChunkCell = 16m
ViewRadiusChunks = 5 → 11×11×11 = 1331 chunks
覆盖体积：176m × 176m × 176m
有效视距：~80m（半径）
滞后防抖：AoiHysteresisChunks = 3（48m 移动才触发重订阅）
```

### 6.2 订阅模型

- **订阅单位**：`characterId` 订阅一组 `mortonKey`（ChunkCell 16m 的 Morton 编码）
- **SubscribeSessionAsync**：玩家进入区域时订阅
- **UnsubscribeSessionAsync**：离开区域时取消
- **RemoveSessionAsync**：断线时清理全部订阅

### 6.3 Fanout 分发

```
ZoneShardGrain 广播
   → 按 ChunkMortonKey 查询订阅者
   → 构造 FanoutEvent{ Packet, TargetSessionIds }
   → IZoneShardFanoutObserver 推送到 Gateway
   → GatewaySyncDispatcher 拉取
   → 按 TargetSessionIds 查 ISessionRegistry
   → IClientPacketSink.Send(endpoint, packet) 下发
```

### 6.4 适用场景与限制

**适用**：中小规模场景（50 人以内同屏），城镇/副本/野外小区域

**不足**：
- 80m 视距对远程战斗/骑乘追逐仍显不足
- 1331 chunks × N 玩家的订阅表内存随人数线性增长
- 快速移动（坐骑 20m/s）时约 2.4s 才更新订阅

## 七、断线重连

### 7.1 重连流程

```
1. 客户端检测断线（心跳超时）
2. 发送 ReconnectResumePacket：
   - LocalCharacterId
   - LastAppliedSnapshotTick
   - LastAppliedDiffSeq
   - BaselineVersion / WorldPatchVersion
3. 服务端验证 baseline 有效性
4. 从 LastAppliedSnapshotTick 开始补发增量
5. 客户端 ClearLocalEntitiesOnDisconnect 重置 AOI
6. 重连后全量订阅恢复
```

### 7.2 边界条件

- 断线超过 1s（60 tick）→ baseline 已被全量覆盖 → 退化为全量重发
- 重连时重置 AOI 订阅状态，确保正确重建完整视野

## 八、性能基线

### 8.1 延迟预算

```
客户端预测：0ms（即时响应）
输入上行：1 RTT/2（TCP，典型 30-80ms）
服务端校验：1 tick（16.67ms @ 60Hz）
修正下行：1 RTT/2
总修正延迟：~1 RTT + 16.67ms

容忍上限：
- RTT < 200ms：预测误差 < 0.5m，不触发 Correction
- RTT 200-400ms：偶发 Correction，重放可恢复
- RTT > 400ms：Correction 风暴，体验劣化
```

### 8.2 带宽预算（100 玩家场景）

| 场景 | 单玩家带宽 | 100 玩家合计 | 目标 |
|------|-----------|-------------|------|
| 全量快照 | 69.8 kbps | 6.98 Mbps | < 100 kbps ✓ |
| 增量压缩（典型） | 44.2 kbps | 4.42 Mbps | < 100 kbps ✓ |

**增量压缩收益**：SnapshotPacket 带宽降幅 66.7%

### 8.3 单 ZoneShard 承载

```
Tick 频率：60Hz
广播频率：每 tick 有变化即广播（~20-60Hz）
全量快照：每 60 tick（1s）
单 EntityDelta：~120-200 bytes（MemoryPack）
保守上限：~200 实体/shard（tick 耗时 < 16ms）
```

## 十二、生产环境风险

### 12.1 Orleans Grain 非重入死锁

- `ZoneShardGrain` 使用 `RegisterTimer` 驱动 60Hz TickAsync
- 若 observer 回调触发对同一 Grain 的调用，将排队等待
- **缓解**：await 模式确保 tick 内广播完成后才进入下一 turn

### 12.2 MovementValidator 高延迟误判

- RTT=300ms 时预测移动 1.8m，方向变化可能导致 drift > 0.5m
- 触发 Correction 风暴
- **建议**：动态阈值 `epsilon = base + k × RTT`

### 12.3 地面采样脆弱性

- 场景流式加载时 Terrain 未加载 → RayCast miss
- 多层地形（洞穴/桥梁）总是命中最高层
- 服务端无物理引擎，信任客户端 PredictedEndZ
- **建议**：服务端引入 heightmap 数据

## 十七、常见坑点与注意事项

| 编号 | 坑点 | 说明 |
|------|------|------|
| P1 | 固定时间步必须对齐 | 客户端 1/60s = 服务端 TickDtSeconds |
| P2 | InputPacket 必须携带 CharacterId | SyncPacketHandler 为单例，不能缓存 |
| P3 | 本地玩家跳过快照 Update | 预测优先，不被远程快照覆盖 |
| P4 | 全量快照 bypassAoiFilter | 新玩家加入必须看到所有在场角色 |
| P5 | 先广播后移除实体 | 避免 Despawn 广播失败产生幽灵 |
| P6 | 120 帧地面保护期 | 防场景未加载时 RayCast miss |
| P7 | Orleans 非重入 | 避免 observer 回调触发同 Grain 调用 |
| P8 | InputHistoryBuffer 必须写入 | 否则 Reconciliation 重放为空→回弹 |
