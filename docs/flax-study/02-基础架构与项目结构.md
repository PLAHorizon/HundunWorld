# FlaxEngine 基础架构与项目结构

> 专题报告：项目结构、场景、Actor、Prefab、资源管理
> 文档来源：https://docs.flaxengine.com/manual/get-started/index.html
> 编制日期：2026-07-25

---

## 一、结论摘要

FlaxEngine 采用统一的项目结构规范，以 `.flaxproj` 为项目入口，`Content` 目录管理资源，`Source` 目录管理代码。场景（Scene）是关卡的基本单位，支持多场景并存和动态加载/卸载。Actor 是场景对象的基本单位，采用树形层级结构。Prefab 提供可复用的对象模板。资源通过唯一 ID 引用，支持自由移动和重命名。

**对 MMORPG 的核心价值**：
- 多场景机制支撑大世界 Chunk 流式加载
- Prefab 支撑角色/NPC/道具模板化
- 资源 ID 系统支撑热更新和版本管理
- 模块化代码组织支撑大型项目协作

## 二、项目结构详解

### 2.1 目录结构

```
<ProjectRoot>/
├── Binaries/              # 编译输出的游戏脚本二进制文件
├── Cache/                 # 编辑器本地缓存（缩略图、Game Cooker 缓存等）
├── Content/               # 所有游戏资源（模型、纹理、设置等）
│   ├── SceneData/         # 场景私有资源目录
│   ├── Shaders/           # 自动导入的着色器资源（从源码）
│   └── GameSettings.json  # 游戏设置资产（固定位置）
├── Logs/                  # 编辑器日志文件和崩溃转储
├── Screenshots/           # 编辑器截图（F12）
├── Source/                # 所有游戏脚本文件（C++ 和 C#）
│   ├── Shaders/           # 着色器源文件
│   ├── <GameModule>/      # 游戏模块代码子文件夹
│   │   └── <GameModule>.Build.cs  # 游戏模块构建脚本
│   ├── GameTarget.Build.cs        # 游戏目标构建配置脚本
│   └── GameEditorTarget.Build.cs  # 编辑器目标构建配置脚本
├── <project_name>.sln     # 项目脚本解决方案文件
└── <project_name>.flaxproj # 项目描述和元数据文件
```

### 2.2 .flaxproj 项目文件

```json
{
    "Name": "My Project",
    "Version": "1.0",
    "Company": "",
    "Copyright": "",
    "GameTarget": "MyProjectTarget",
    "EditorTarget": "MyProjectEditorTarget",
    "References": [
        { "Name": "$(EnginePath)/Flax.flaxproj" },
        { "Name": "$(ProjectPath)/Plugins/MyPlugin/MyPlugin.flaxproj" }
    ],
    "DefaultScene": "297f662e43c41143e406ae9ab85097f2"
}
```

**关键点**：
- JSON 格式，适合版本控制
- `References` 支持引用引擎和插件项目
- `DefaultScene` 指定启动场景
- `GameTarget`/`EditorTarget` 指定构建目标类名

### 2.3 代码模块组织

Flax 使用 **Binary Modules** 概念组织代码：

- 主游戏代码通常在 `Source/Game` 或 `Source/<ProjectName>` 模块
- 支持多模块拆分（如 Editor-only 模块、Client/Server 分离模块）
- 每个模块有对应的 `.Build.cs` 构建脚本
- 模块间通过 `PublicDependencies`/`PrivateDependencies` 引用

**MMORPG 建议模块划分**：
```
Source/
├── Game.Core/          # 核心游戏逻辑（共享）
├── Game.Client/        # 客户端专属逻辑
├── Game.Server/        # 服务器专属逻辑
├── Game.Editor/        # 编辑器扩展工具
└── Game.Networking/    # 网络同步逻辑
```

## 三、场景系统

### 3.1 场景基本概念

- **Scene** 是游戏关卡，由 Actor 组成
- 场景是 JSON 格式资产，包含序列化的场景对象
- **支持多场景并存**：可同时打开/编辑多个场景
- 支持**动态加载/卸载**场景

### 3.2 场景操作

| 操作 | 方式 |
|------|------|
| 创建场景 | Content 窗口 → 右键 → New → Scene |
| 打开场景 | 双击场景资源 |
| 叠加加载 | 拖拽场景到编辑器视口（Additive Load） |
| 场景属性 | 选择 Scene Actor 编辑（Static Flags、Transform、Lightmap） |

### 3.3 场景数据

- 场景资源存储在 `Content/` 目录
- 场景私有数据存储在 `Content/SceneData/` 目录
- 场景可整体变换 Transform（平移/旋转/缩放所有子对象）
- 支持 Static Flags 批量设置

### 3.4 多场景与大世界

**官方机制**：
- 多场景可同时加载
- NavMesh Tiles 按场景分块，运行时合并
- 场景加载是异步的

**MMORPG 大世界设计建议**：
```
World/
├── Chunk_0_0.scene    # 区块 (0,0)
├── Chunk_0_1.scene    # 区块 (0,1)
├── Chunk_1_0.scene    # 区块 (1,0)
└── ...
```

- 玩家周围 N×N 区块保持加载
- 远处区块异步卸载
- NavMesh 随区块自动管理
- **待验证**：大量场景同时加载的内存峰值

## 四、Actor 系统

### 4.1 Actor 基本概念

- Actor 是场景的基本对象
- 树形层级结构（父子关系）
- 每个 Actor 有 3D Transform（位置、旋转、缩放）
- 子 Actor 继承父 Actor 的 Transform
- 可附加 C# 脚本
- 可运行时动态创建/销毁

### 4.2 Actor 类型

| 类别 | 类型 |
|------|------|
| **相机** | Camera |
| **光照** | Directional Light、Point Light、Spot Light、Sky Light |
| **环境** | Sky、Skybox、Environment Probe、Exponential Height Fog |
| **静态** | Static Actor（Static Model） |
| **物理** | Rigid Body、Character Controller、Colliders、Joints |
| **动画** | Animated Model、Bone Socket |
| **音频** | Audio Source、Audio Listener |
| **UI** | UI Canvas、UI Control |
| **特效** | Particle Effect、Decal |
| **导航** | Nav Mesh Bounds Volume、Nav Link |
| **其他** | Empty Actor、Text Render、Sprite Render、Terrain、Scene Animation Player、PostFx Volume |

### 4.3 Actor 使用

- **放置**：编辑器中从 Toolbox 拖拽或右键创建
- **选择**：Scene 窗口或视口点击
- **变换**：移动（W）、旋转（E）、缩放（R）
- **脚本附加**：Properties 窗口 → Add Script

## 五、Prefab 系统

### 5.1 Prefab 概念

- Prefab 是**可复用的 Actor 模板**
- 存储为资产，可多次实例化
- 支持嵌套 Prefab
- 修改 Prefab 影响所有实例（可选覆盖）

### 5.2 Prefab 工作流

1. 在场景中创建 Actor 并配置
2. 拖拽到 Content 窗口创建 Prefab
3. 从 Content 拖拽 Prefab 到场景实例化
4. 代码中通过 `PrefabManager.SpawnPrefab` 实例化

### 5.3 代码使用

```csharp
public class GameManager : Script
{
    public Prefab PlayerPrefab;
    
    public void SpawnPlayer(Vector3 position)
    {
        var player = PrefabManager.SpawnPrefab(PlayerPrefab, position);
        // 配置玩家...
    }
}
```

### 5.4 MMORPG 应用

| 用途 | 说明 |
|------|------|
| 角色模板 | 玩家角色、NPC、怪物 |
| 道具模板 | 装备、消耗品、材料 |
| 特效模板 | 技能特效、环境特效 |
| UI 模板 | 重复使用的 UI 组件 |

## 六、资源管理

### 6.1 资源基本概念

- **Asset** 是持有资源数据的文件
- 可从外部导入（模型、音频、纹理）或编辑器内创建（材质、场景）
- 每个资源有**唯一 ID**
- 可自由移动/重命名，引用自动更新

### 6.2 资源类型

| 类别 | 类型 |
|------|------|
| **模型** | Models、Skinned Model |
| **纹理** | Textures、Cube Textures、IES Profiles |
| **材质** | Materials、Instanced Materials |
| **场景** | Scenes |
| **物理** | Physical Materials、Collision Data |
| **预制体** | Prefab |
| **动画** | Anim Graph、Animation、Skeleton Mask |
| **字体** | Font Asset |
| **粒子** | Particle Emitter、Particle System |
| **过场** | Scene Animation |
| **自定义** | Custom Assets |

### 6.3 资源引用

**编辑器中**：
- 拖拽到 Asset Picker 控件
- 拖拽到视口（模型→Static Model，材质→应用到模型）

**脚本中**：
```csharp
public class SetMaterial : Script
{
    [Tooltip("Material to assign to the model")]
    public Material Material;  // 序列化资源引用

    public override void OnStart()
    {
        Actor.As<StaticModel>().SetMaterial(0, Material);
    }
}
```

### 6.4 资源加载

**同步加载**：
```csharp
var model = Content.Load<Model>(modelId);
```

**异步加载**：
```csharp
var task = Content.LoadAsync<Model>(modelId);
// 等待完成...
```

**待验证**：
- 引用计数和自动卸载机制
- 手动卸载 API
- 加载优先级和流式加载策略

## 七、Game Settings

### 7.1 配置入口

- 固定位置：`Content/GameSettings.json`
- JSON 格式，适合版本控制
- 引用其他设置资产

### 7.2 主要设置项

| 设置 | 说明 |
|------|------|
| Product Name | 游戏名称 |
| FirstScene | 启动场景 |
| Time | 时间设置（帧率等） |
| Audio | 音频设置 |
| Layers And Tags | 层和标签 |
| Physics | 物理设置 |
| Input | 输入设置 |
| Graphics | 图形设置 |
| Navigation | 导航设置 |
| Game Cooking | 构建设置 |
| Streaming | 流式加载设置（Texture Groups） |
| Custom Settings | 自定义设置 |
| 平台设置 | Windows/PS4/PS5/Xbox/Switch/macOS/iOS/Web |

### 7.3 运行时访问

```csharp
using FlaxEditor.Content.Settings;
using FlaxEngine;

public class TestSettings : Script
{
    public override void OnEnable()
    {
        var gameSettings = GameSettings.Load();
        Debug.Log("Game name: " + gameSettings.ProductName);
        
        var timeSettings = GameSettings.Load<TimeSettings>();
        Debug.Log("Draw FPS: " + timeSettings.DrawFPS);
    }
}
```

## 八、编辑器基础

### 8.1 编辑器界面

- **可停靠窗口**：所有窗口可自由拖拽、停靠、浮动
- **视口**：3D 场景编辑
- **Content**：资源管理
- **Scene**：场景层级
- **Properties**：属性编辑
- **Toolbox**：Actor 创建

### 8.2 Play In-Editor (PIE)

- 在编辑器内直接测试游戏
- 支持多种模式（Play、Pause、Step）
- 游戏逻辑仅在 PIE 时模拟（除非标记 `[ExecuteInEditMode]`）

### 8.3 调试工具

- **DebugDraw**：可视化调试绘制
- **Profiler**：性能分析窗口
- **脚本调试**：支持 Visual Studio、VS Code、Rider 断点调试

## 九、对 MMORPG 客户端的落地建议

### 9.1 项目结构建议

```
HundunWorld/
├── Content/
│   ├── Characters/       # 角色资源
│   ├── Environments/     # 环境资源
│   ├── Effects/          # 特效资源
│   ├── UI/               # UI 资源
│   ├── Audio/            # 音频资源
│   ├── Scenes/           # 场景（按区域/Chunk 组织）
│   │   ├── World/        # 大世界 Chunk
│   │   ├── Dungeons/     # 副本
│   │   └── UI/           # UI 场景
│   └── Settings/         # 配置资源
├── Source/
│   ├── Game.Core/        # 核心逻辑
│   ├── Game.Client/      # 客户端逻辑
│   ├── Game.Networking/  # 网络逻辑
│   └── Game.Editor/      # 编辑器工具
└── Plugins/              # 插件
```

### 9.2 场景管理策略

1. **大世界**：按 Chunk 划分场景，流式加载/卸载
2. **副本**：独立场景，进入时加载，退出时卸载
3. **UI**：独立 UI 场景或 Canvas，常驻或按需加载
4. **过渡**：Loading 场景处理资源预加载

### 9.3 Prefab 使用规范

1. 角色、NPC、怪物使用 Prefab 模板
2. 技能特效使用 Particle System Prefab
3. UI 组件使用 UI Prefab
4. 命名规范：`Prefab_<Category>_<Name>`

## 十、常见坑点与注意事项

| 编号 | 坑点 | 说明 |
|------|------|------|
| P1 | 场景叠加加载 | 拖拽到视口是 Additive Load，不会卸载现有场景 |
| P2 | 资源 ID | 资源通过 ID 引用，不要依赖文件路径 |
| P3 | GameSettings 位置 | 必须在 `Content/GameSettings.json`，固定位置 |
| P4 | 模块依赖 | 模块间依赖需在 .Build.cs 中显式声明 |
| P5 | Prefab 覆盖 | 实例可覆盖 Prefab 属性，注意同步问题 |
