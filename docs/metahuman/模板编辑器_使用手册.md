# 数字人模板编辑器 · 使用手册

> 面向：要在编辑器里做数字人模板、核对模板与资产、导入 UE MetaHuman 导出物、给数字人绑骨骼动画的人。
> 代码位置：`HundunWorld/Plugins/MetaHuman/Source/MetaHumanEditor/MetaHumanTemplateEditorWindow.cs`
> 相关文档：`docs/MetaHuman对标UE5.8_方案与决策清单.md`（设计与决策）、`docs/MetaHuman_完成度审计_2026-10-22.md`（实测证据）

---

## 1. 这个工具解决什么

数字人的所有可改数值，最终都要落到一张映射表上：**玩家滑杆 → 资产里真实存在的 blendshape / 骨骼 / 材质参数**。
这张表就是「模板」（`Template_<id>.json`）。表写错的表现非常难受——**改了数值，模型一动不动，且不报错**。
本窗口的全部设计都围绕这一点：每一步都产出文本证据，缺什么必须点名。

打开方式：菜单 **Tools → 数字人模板编辑器**。

## 2. 三分钟上手

1. 打开窗口，第一件事点 **「环境自检」**。它只读不写，会把模板根目录、盘上有哪些模板、当前模板校验结果、
   模型资产能不能装载、UE 导出目录里有什么、内嵌表新不新，一次全摊在报告里。
2. 报告里任何一行写着「未解析 / 装载失败 / 不存在 / ✗」，**先修那一行再干别的**——
   其它按钮的结果在修好之前都不可信。
3. 然后按下面的三条工作流选一条走。

窗口上记住一件事就够了：**动作名里带「预览 / 核对 / 扫描 / 自检」的都不写盘，带「导入 / 另存 / 回填 / 写入并保存」的会写盘**
（其中「回填 morph」只改内存，要再点「另存模板」才落盘）。

## 3. 界面分区

| 分区 | 格子 | 旁边的按钮 | 会不会写盘 |
|---|---|---|---|
| 模板 | 当前模板（下拉） | 重载 | 否 |
| 模板 | 输出模板 Id | 另存模板 | **是**（写 `Template_<id>.json`） |
| ① 从 UE 导出目录导入 | UE 导出目录 | 浏览目录 / 扫描预览 | 否（浏览完会自动扫一次） |
| ① 从 UE 导出目录导入 | 资产输出到 | 导入并生成模板 | **是**（导资产 + 写模板） |
| ② 模板与资产核对 | 模型资产 | 浏览资产 / 核对绑定 / 回填 morph | 回填只改内存 |
| ③ 骨骼动画绑定 | 目标模型 / 来源骨架 / 动画目录 | 预览映射 / 写入并保存 | 只有「写入并保存」写 |
| 报告 | 只读多行文本框 | 环境自检 / 复制报告 / 打开模板目录 / 使用手册 | 否 |

- **当前模板**：下拉列表每次展开都重新扫盘，新存的模板不用重启就能看到。
- **输出模板 Id**：被「另存模板」和「导入并生成模板」共用。留空时这两个按钮会直接拒绝执行并告诉你缺哪一格。
- **模型资产**：一条或多条 `Content/...` 路径，用 `;` 隔开。一个角色通常由头/身/眼等多份网格组成，
  只填一份的话，另一份身上的 morph 会被报成「缺失」。
- 每一格的填写内容在关窗时记到 `HundunWorld/Cache/MetaHumanTemplateEditorWindow.json`，下次打开自动回填；
  这个文件可以随时删，删了不影响任何功能。

## 4. 工作流 A：导入一份 UE MetaHuman 导出物

**前置**：手上要有 UE 侧 MetaHuman 管线的导出物——一个目录，里面直接放着
FBX/OBJ（模型）、EXR/PNG（贴图组，文件名里带 `basecolor`/`normal`/`cavity`/`specular` 等槽位词）、
可选的 `template_description.json`。
`.dna` 容器不在 Flax 侧解析（PCA identity 模型不移植），形状改由资产自带的 blendshape 与面部关节承担。

1. 「UE 导出目录」→ 点 **浏览目录** 选中那个文件夹。选完窗口会自动跑一次**扫描预览**，
   报告里列出：模型几个、认出哪些贴图槽位、描述 JSON 几个、以及全部告警。
2. 想看清楚但不想动手，就反复点 **扫描预览**——它不写任何文件。
3. 确认「资产输出到」（默认 `Content/MetaHuman`）和顶部「输出模板 Id」（默认 `metahuman.imported`）填好。
4. 点 **导入并生成模板**。它会：把每个模型用引擎脚本化导入导成 `.flax`（**强制 `ImportBlendShapes=true`**，
   引擎默认是关的，关掉等于所有形状参数静默失效）→ 用导入出来的资产真扫一遍 blendshape 名录 →
   以 `metahuman.face_archetype`（没有则 `metahuman.body_base`）为底派生一份新模板 → 写 `Template_<输出Id>.json`。
5. 报告里逐条看：导入成功几个 / 失败几个、模板落到哪个绝对路径、绑定核对结果、告警清单。

**导入后游戏里还没生效**：见 §7 的生效链。

**已知限制（2026-10-22 用真导出物实测后写在这里）**：派生新模板时底模板固定取 `metahuman.face_archetype`
（读不到才退 `metahuman.body_base`）。所以**导身体会得到一份带着全部脸部参数的模板**——
报告里会明写「底模板 metahuman.face_archetype；HeadAsset 记为第一份导入资产」，
看到 `缺失槽位 75 / 缺失骨骼目标 363` 就是这个意思，不是资产坏了。想只要身体，就改用工作流 B 在身体模板上回填。

## 4b. 这一轮实测到的证据（可复跑）

`Output/mhbody`（UE 5.8.3 导出的 glb 身体）走完整条 A：扫描认出 2 个模型 + `basecolor` 槽位 →
导入 2 份 `SkinnedModel` 资产 → 生成模板 → 报告如实说出「这份身体没有 blendshape」。
工作流 B 用真头部资产（`Content/Character/Models/head_mh/Ada_FaceMesh_conformhead4.flax`，
876 骨骼 / **821 blendshape**）核对脸模板：598 参数、名录 37、可承载 552；
回填后 1419 参数、名录 858、可承载 1373；另存 1,951,909 字节。
工作流 C 用 ALS 骨架 → Ada 身体：映射 54 个节点（同名 2 + 别名 51 + 槽位 1），
125 份动画补了动画源条目并 `Save` 成功。

同一轮里修掉了四个真实缺陷（它们叠在一起，所以单独看每一个都像"环境不对"）：

| 缺陷 | 表现 | 修法 |
|---|---|---|
| `Editor.Import` 返回值极性反了（true=失败） | 导入失败被记成成功、成功被记成失败 | 判据改成「盘上有没有这份 `.flax`」，返回值只进文案 |
| `new ModelTool.Options()` 的 `Type` 零值是 `Model` | 导出来的资产 `kind=Model`，骨骼与 morph 全不解析，报告却"导入成功" | 以 `ModelTool.Options.Default` 当底座 + 显式 `Type=SkinnedModel`，刷库后再按 SkinnedModel 复核 |
| 资产路径不带 `.flax` 时 `Content.Load` 与 `GetAssetInfo` 双双读空 | 模板里存的正是这种写法 ⇒「导入成功」与「模板 0 个 morph」同时成立 | `MetaHumanAssetUtil.LoadSkinnedModel` 两种写法都试 + 要求 `IsLoaded` + Guid 兜底，四处共用 |
| 回填给落单的侧向名留着 `Side` 却没有 `PairId` | 「回填→另存」被校验门拦死（真资产上 8 条错误），整条 B 是死路 | 配对改为按参数查（能配到本批之外的对岸）+ 落单的降回 `Side=None`；配 11 条断言，摘掉修复即红 4 条 |


## 5. 工作流 B：让模板跟上手上的资产

这是日常用得最多的一条，用来回答「这份资产到底能不能被这个模板驱动」。

1. 「模型资产」→ **浏览资产**（可多选 `.flax`）或直接粘路径。
2. 「当前模板」下拉里选中要核对的那个。
3. 点 **核对绑定**（只读）。报告字段读法：

   | 报告里的字段 | 含义 | 该怎么办 |
   |---|---|---|
   | `缺失 morph (N)` | 模板引用了资产里没有的 blendshape | 名字不同族（模板写的是 `.dna` 族名，资产里是 UE 网格族名）或资产没开 blendshape 导入 |
   | `缺失骨骼目标 (N)` | 骨骼缩放/位移类参数指向不存在的骨骼 | 补 `SkeletonSlotMap` 候选名，或删掉这条效果 |
   | `缺失槽位 (N)` | 规范槽位（head/body/jaw…）一个候选名都没命中 | 看资产骨架命名族，往槽位表里加别名 |
   | `资产里未被模板引用的骨骼` | 反向信息：资产有、模板没用 | 通常无害，是「还能不能加参数」的线索 |
   | `参数总数 / morph 名录` | 模板规模 | 回填前后对比这个数字 |
   | 某资产 `无 blendshape（导入未开 ImportBlendShapes？）` | 该资产形状数为 0 | 用 `asset_import` 重导并打开 blendshape 导入 |

4. 想让资产里多出来的 blendshape 变成滑杆 → 点 **回填 morph**。报告会写「新增 N 根（参数 X → Y）」，
   并明确一句：**这一步只在内存里**。
5. 点 **另存模板** 才会写盘（写到 `Template_<输出模板 Id>.json`）。
   保存前会跑一遍模板自检（`Validate`）：Id 重复、区间非法、侧向参数没配 `PairId`、
   引用了名录里不存在的 blendshape、贴图效果两张图都没给、死预设……**任何一条错误都会拒绝保存并把清单打出来**。
6. 回填完忘了另存就点「重载」或关窗 → 报告里会先警告你「还没另存，重载会丢掉它」。

## 6. 工作流 C：给数字人绑一批骨骼动画

让一份在别的骨架上做的动画（ALS / UEFN 人偶…）能在数字人骨架上播。
走的是引擎原生通道 `SkinnedModel.SkeletonRetargets`（节点名映射表），不是逐帧搬姿势。

1. 「目标模型」= 数字人那份 SkinnedModel；「来源骨架」= 动画原本绑的那份。
2. 点 **预览映射**（不写盘）。报告给出映射节点数、未映射数、来源节点总数。
   命中是分档的：**同名 → 忽略大小写 → 左右镜像 → 别名表 → 槽位表**，越往后越需要人看一眼。
   别名表与槽位表来自 **「当前模板」** 那一格——换模板就可能换一套映射结果，先选对模板再预览。
3. 「动画目录」填上动画所在目录（如 `Content/Animations/als`）。**这一步不是可选的洁癖**：
   引擎是按**动画资产 Id** 查 `SkeletonRetargets` 的，只写「来源骨架模型 Id」的条目在播放时永远命中不了。
4. 点 **写入并保存**。它会写骨架映射条目 + 给目录里每份动画补一条「动画 Id → 来源骨架」条目，
   然后保存目标资产（保存失败会明说，不会把失败报成成功）。
5. 验证：关掉再打开该 SkinnedModel，条目应该还在；PIE 里播一次动画。

## 7. 生效链：为什么「改了模板，游戏里没反应」

**编辑器窗口读的是盘上的 JSON，而游戏/PIE 读的是烘进程序集的那一份内嵌表。**
所以改完 `Template_*.json` 之后，运行期不会自己变。完整链条：

```bash
# 1) 重新烘焙内嵌表（产物：Source/MetaHuman/Core/MetaHumanBakedTables.cs）
python Tools/MetaHumanBakeTables.py

# 2) 重编插件（两个目标一起，实测可用的命令）
"C:/Program Files (x86)/Flax/Flax_1.13/Binaries/Tools/Flax.Build.exe" \
  -workspace="C:/Works/GitHubProjects/HundunWorld/HundunWorld/Plugins/MetaHuman" \
  -buildTargets=MetaHumanTarget,MetaHumanEditorTarget \
  -product=Editor -configuration=Development -platform=Windows -arch=x64 -build

# 3) 重启编辑器（插件脚本在工程加载时编译，热重载不覆盖运行期那份）
```

窗口里的 **「环境自检」会直接替你比这一步**：它比较最新模板 JSON 与最新 `MetaHuman.CSharp.dll` 的修改时间，
JSON 更新就报 `✗ 运行期用的还是旧内嵌表`。

改完顺手跑离线门（不依赖编辑器）：

```bash
dotnet build Tools/MetaHumanEditorCompileCheck -c Debug --no-incremental   # 编辑器模块编译门
dotnet run --project Tools/MetaHumanVerify                                  # 纯核断言集
```

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 下拉列表是空的 / 报「模板根目录未解析」 | `Plugins/MetaHuman/Content/Templates` 没找到 | 确认插件目录完整；看自检里列出的候选路径 |
| 报「模板文件里的 TemplateId 与请求的不一致」 | 文件名和 JSON 里的 Id 对不上 | 以内容为准，改文件名或改 Id |
| 核对报告里 morph 全缺 | 资产导入没开 `ImportBlendShapes` | 重导该资产；导入器那一步是强制开的 |
| 「导入并生成模板」报告 0 个 | 目录选错（选了上一级）、或里面没有 FBX/OBJ | 用「扫描预览」先确认模型候选数 |
| 回填后重开窗口参数又少了 | 没点「另存模板」 | 回填只改内存 |
| 绑了动画但游戏里不放 | 没填「动画目录」，缺动画源条目 | 补填后重新「写入并保存」 |
| 报告太长看不过来 | — | 点「复制报告」，全文进剪贴板 |
| 想直接看盘上模板文件 | — | 点「打开模板目录」 |

## 10. 与 MCP 工具的关系

同一套底层能力也有脚本入口，适合批量与取证（编辑器菜单里的 `HundunAgent`）：

| 工具 | 对应窗口动作 |
|---|---|
| `metahuman_template`（`action` = `scan` / `import` / `check` / `backfill` / `save`） | 工作流 A 与 B 的五个按钮 |
| `metahuman_bind`（`apply=false` 预览、`apply=true` 落盘、`animationsDir` 补动画条目） | 工作流 C 的两个按钮 |
| `metahuman_inspect` / `metahuman_drive` / `metahuman_fixture` / `metahuman_selftest` | 运行期侧：读角色、驱动参数、搭夹具、跑 PIE 自检 |

窗口负责「看得见、改得动」，工具负责「批量跑、留回执」；两者调用同一批实现
（`MetaHumanUEImporter` / `MetaHumanRigBinder` / `MetaHumanAnimationBinder` / `MetaHumanTemplateStore`），
判定口径完全一致——同一个 `check` 在两边跑出同样的 552/598 才算数。

连接器里的工具清单是**连接时缓存**的：新加的工具要先重启编辑器，或在客户端重连后再调
（直接对 `http://localhost:21901/mcp` 发 JSON-RPC 可以绕开这层缓存）。
