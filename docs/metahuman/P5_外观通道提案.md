## 2. 要加的东西（最小充分集）

设计原则：外观是**不透明 blob + 自描述版本**，服务端不参与求解，只做存储、校验和转发。
这样加参数不需要同步改服务端类型，也不会有「服务端不认识新字段就丢弃」的静默失效。

## 3. 预算与兼容

- 一条外观 = 差量条目 ×（4 字节值 + 2 + 键名字节）+ 头部约 80 字节。
  玩家改 30 个参数、键名平均 22 字节 ≈ **0.9KB/角色**；AOI 广播多玩家时按 `Checksum` 去重，
  同一角色外观不变就不再随 spawn 重发（沿用现有 DS 通道的按会话补发口径）。
- 兼容老角色：`MetaHumanLook == NULL` 一律按「模板默认值」渲染，不需要数据回填。
- 模板加参数：`TemplateParamCount` + `ValidateAgainst()` 会在槽位漂移时大声失败而不是整体平移旧存档。

## 4. 风险点（落地时要盯）

1. `AppearanceInfo` 是老数据的唯一载体，**不能改名不能改顺序**；新 payload 并存，等迁移完再谈退役。
2. Orleans 新旧 Silo 混跑会 `TypeLoadException`：改接口后必须整套重启（既有教训）。
3. 客户端 `Game.Build.cs` 的 DLL 清单与 Flax Tools 刷新清单要同步，否则编辑器吃旧 DLL、改了没反应。
4. 发布位是**服务端**判定，不是客户端 UI 判定；否则改包就能绕过。
