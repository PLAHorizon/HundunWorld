# 远程角色闪跳阈值优化计划

## Context（背景与目标）

**问题**：MMORPG 网络同步中，远程角色位置由 [InterpolationSystem.cs](file:///c:/Works/GitHubProjects/HundunWorld/Horizon.Game.ECS.Arch/Systems/InterpolationSystem.cs) 在 Render 阶段做 Lerp 平滑追赶。当某个新快照的 Target 与当前插值位置距离超过 `TeleportThresholdMeters`（当前 50m）时，代码走 [L183-L198](file:///c:/Works/GitHubProjects/HundunWorld/Horizon.Game.ECS.Arch/Systems/InterpolationSystem.cs#L183-L198) 的硬跳分支——**直接把 X/Y/Z 设为 Target**，视觉上表现为角色"闪跳/瞬移"。

阈值内（≤50m）走 Lerp 平滑追赶，看上去流畅；阈值外（>50m）瞬移，体验割裂。触发场景包括：长时间断网恢复后位置累积漂移、AOI chunk 重新订阅时的位置对齐、服务端 tick 异常等。

**目标**（用户原话）：
1. 扩大阈值范围 —— 让更多漂移场景落入平滑 Lerp 区
2. 减少闪跳对游戏可游玩性的影响 —— 真正超过阈值时不要"硬瞬移"

**方案**：把现有「2 档（Lerp / 硬跳）」改为「3 档（Lerp / 加速混合 / 硬跳）」：
- `dist ≤ TeleportThresholdMeters`（50→**100m**）：原有 Lerp 平滑追赶，**仅扩大范围**
- `TeleportThresholdMeters < dist ≤ HardSnapThresholdMeters`（新档，100~500m）：**时间锚定加速混合**，200ms 内用 smoothstep 缓动从当前位置过渡到 Target，视觉上是"快速冲刺"而非"瞬移"
- `dist > HardSnapThresholdMeters`（500m）：保留硬跳，专处理真传送（复活、跨地图），避免长距离混合看起来像"飞行"

### 2. [Horizon.Game.ECS.Arch/Systems/InterpolationSystem.cs](file:///c:/Works/GitHubProjects/HundunWorld/Horizon.Game.ECS.Arch/Systems/InterpolationSystem.cs)

#### 2.1 调整阈值属性（L59-L94 区域）

- `TeleportThresholdMeters` 默认值 `50f` → **`100f`**，更新 L66-L70 注释说明"原 50m 提升到 100m，覆盖更长断网恢复场景"
- 新增 `HardSnapThresholdMeters`（默认 `500f`）：超过此距离仍走硬跳，专处理真传送
- 新增 `TeleportBlendDurationSeconds`（默认 `0.2f` = 200ms）：加速混合时长。200ms 在 60fps 下约 12 帧，足够可见又不至于像"飞行"

#### 2.2 重写 Active 分支传送逻辑（L175-L248）

新流程：

```
Active 状态入口：
1. 若 TeleportBlendRemainingSeconds > 0（混合进行中）：
   - elapsed = duration - remaining；alpha = clamp(elapsed/duration, 0, 1)
   - smoothedAlpha = alpha² × (3 - 2×alpha)  // smoothstep 缓动
   - X = Lerp(Start, Target, smoothedAlpha)；Yaw 同理（含 ±π 最短路径归一化）
   - remaining -= dt；if remaining <= 0：snap 到 Target，清零 Remaining+Duration
   - 触发 OnTeleportJump 诊断（仅在混合"启动"那一帧触发一次，使用 blend 标记去重）
   - return（跳过普通 Lerp）
2. 计算 distSq（当前位置 vs Target）
3. 若 distSq > hardSnapThresholdSq：硬跳到 Target，清零混合状态，OnTeleportJump，return
4. 若 distSq > teleportThresholdSq：启动混合
   - 记录 Start = 当前 X/Y/Z/Yaw
   - Duration = TeleportBlendDurationSeconds；Remaining = Duration
   - 立即推进一帧（remaining -= dt，计算 alpha，更新位置）—— 避免空帧
   - OnTeleportJump 触发一次（distance = sqrt(distSq)）
   - return
5. 否则（distSq ≤ teleportThresholdSq）：原有 Lerp + 前向预测逻辑不变
```

#### 2.3 诊断事件契约

`OnTeleportJump` 接口签名不变，仍只在传送处理"启动"时调用一次：
- 硬跳：启动=完成，调用 1 次
- 混合：启动时调用 1 次（后续混合帧不重复调用）

这样 `SyncDiagnosticsSinkImpl` 的日志语义保持"每次传送触发一条日志"，不破坏现有诊断契约。

## 设计权衡说明

| 决策点 | 选择 | 理由 |
|---|---|---|
| 阈值扩大到多少 | 50→100m | 2x 当前值，覆盖更长断网累积；不过大避免真正的传送也走 Lerp 导致"飞行" |
| 是否引入 HardSnap 兜底 | 是，500m | 真传送（复活/跨地图，通常 >500m）应瞬移而非混合，500m@200ms=2500m/s 已是"模糊冲刺"上限 |
| 混合时长 | 200ms | MMO 通用 150-300ms 区间；60fps 下 12 帧足够可见，不至"飞行感" |
| 缓动函数 | smoothstep（`t²(3-2t)`） | 与本项目既有 `InterpolationSystemSmoothStepTests` 验证的缓动同族，ease-in-out 视觉自然 |
| 时间锚定 vs 指数 Lerp | 时间锚定（start/target/elapsed） | 指数 Lerp 收敛时间不确定（依赖 dt），时间锚定保证 200ms 必达，确定性高 |
| 是否复用 StartX/Y/Z | 否 | 该字段被 FlaxActorSyncSystem 的 IsWalking 回退分支读取，复用会污染动画判断 |
| 诊断事件 | 复用 OnTeleportJump，启动时调用 1 次 | 不破坏 ISyncDiagnosticsSink 接口契约，日志语义不变 |
