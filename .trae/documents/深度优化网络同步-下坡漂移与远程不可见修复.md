# 深度优化网络同步：下坡Z漂移与远程角色不可见修复

## 摘要

客户端角色停留一段时间后移动会被拉回起点，且无法看到远程角色移动。经深度分析，**核心根因**是服务端 `MovementValidator` 的地面约束 fallback 条件 `dzPred >= 0f` 无法处理下坡场景：客户端下坡时 `PredictedEndZ < 服务端重力计算Z`，导致 `dzPred < 0`，fallback 不触发，服务端 Z 持续漂移 → drift 超阈值 → Correction 风暴 → 角色被拉回。同时服务端权威 Z 错误导致广播给其他客户端的 delta 高度错误。

#### 问题1：MovementValidator fallback 条件 BUG（根因）

## 阶段2：远程角色网络抖动冻结修复（Idle Dead Reckoning）

### 问题根因

远程角色在 `SnapshotApplySystem` 状态机中，`Active → Idle` 阈值为 0.5 秒（服务端心跳间隔 100ms，仅 5 次心跳未到达即冻结）。进入 `Idle` 状态后 `InterpolationSystem` 直接 `return` 冻结位置，**即使实体正在移动**。

多客户端网络拥塞时（>3 个客户端），0.5 秒抖动常见，导致：
1. 远程角色频繁 `Active → Idle → Active` 切换，视觉"一顿一顿"
2. `Idle` 期间完全冻结，恢复 `Active` 时 Lerp 追赶产生"加速冲刺"视觉突变
3. `SnapshotApplySystem` 已在 `HandleUpdate` 中记录 `LastVelocityXZ` "供 Idle/Stale 状态下做 dead reckoning"，但 `InterpolationSystem` 从未在 Idle/Stale 中使用它

## 假设与决策

1. **假设**：服务端无法注入 FlaxEngine.Physics 的 GroundHeightSampler，需依赖客户端 `PredictedEndZ` 作为地面参考。
2. **决策**：修改1采用 `MathF.Abs(dzPred) < 10f` 而非注入 GroundHeightSampler，因为：

   * 客户端 `PredictedEndZ` 已包含 GroundHeightSampler 约束结果，语义上就是"客户端认为的地面高度"

   * 服务端无地形数据，注入 GroundHeightSampler 需要额外构建 heightmap 服务，成本高

   * 10m 上限 + drift 校验已提供足够的反作弊保障
3. **决策**：isGrounded 判断基于 Z 变化量（`|zChange| < 0.05f`）而非 Vz，因为修改1中下坡场景保留了非零 Vz，用 Vz 判断会误判为"在空中"。
4. **决策**：修改4（输入间隙处理）信任客户端 ReportedEnd，因为客户端的预测包含了所有输入的累积效果，比服务端从错误起点回放更准确。
