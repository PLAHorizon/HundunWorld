## 简介
本系统基于Orleans框架实现，采用Grain模型对游戏中的角色进行统一管理。通过`IPersistentState<CharacterState>`实现状态的自动持久化，并结合数据库上下文完成数据同步。系统支持角色创建、登录、移动、战斗、装备、技能等完整生命周期操作，具备高并发处理能力。

## 核心组件

### CharacterGrain 类
作为角色的核心业务逻辑载体，继承自 `Grain<CharacterState>` 并实现 `ICharacterGrain` 接口。每个角色实例由唯一的整数键标识，封装了角色的所有行为和状态。

### ICharacterGrain 接口
定义了角色Grain对外暴露的所有异步方法，包括角色创建、进入游戏、移动、战斗、社交等功能，是客户端与服务端交互的主要契约。

## 状态管理与持久化机制

### IPersistentState<CharacterState> 模式
系统使用 Orleans 提供的 `IPersistentState<T>` 接口来管理角色状态。在 `CharacterGrain` 构造函数中通过依赖注入获取：

```csharp
[PersistentState("character", "GameStore")] 
IPersistentState<CharacterState> characterState
```

该配置指定了状态名称为 "character"，存储提供程序为 "GameStore"（通常对应数据库连接）。

### CharacterState 结构
包含两个核心字段：
- `CharacterInfo`: 角色详细信息对象
- `IsOnline`: 在线状态标志

此结构通过 MemoryPack 和 Orleans 序列化机制高效地在内存与存储之间转换。

### 与 GameEntityContext 的数据同步策略
当状态未从持久化存储加载时（如首次激活），系统会尝试从 `GameEntityContext` 查询数据库并填充状态：

```csharp
var characterEntity = await _gameCharacterContext.QueryFirstOrDefaultAsync(c => c.Id == CharacterId);
if (characterEntity != null)
{
    _characterState.State.CharacterInfo = _mapper.Map<CharacterInfo>(characterEntity);
    await _characterState.WriteStateAsync();
}
```

更新操作则先修改内存状态，再显式调用 `WriteStateAsync()` 同步到数据库。

## 角色生命周期管理

### 创建角色 (CreateCharacterAsync)
1. 验证用户是否被封禁
2. 对角色名执行敏感词过滤
3. 检查角色名唯一性
4. 映射请求至 `CharacterEntity`
5. 设置默认值（等级1、经验0等）
6. 写入数据库
7. 更新Grain状态并持久化

返回包含新角色信息的成功响应。

### 进入游戏 (EnterGameAsync)
1. 检查角色数据是否已加载
2. 将 `IsOnline` 状态设为 true
3. 调用 `WriteStateAsync()` 持久化在线状态
4. 返回包含角色信息的响应

### 移动操作 (MoveAsync)
1. 校验角色是否在线
2. 更新 `CharacterInfo.Position` 坐标
3. **注意：此处注释明确指出不应频繁写状态**，实际应广播给附近玩家并在适当时机批量持久化

### OnActivateAsync 激活逻辑
Grain激活时自动执行：
- 记录激活日志
- 若内存状态为空，则从数据库恢复
- 成功恢复后立即持久化一次以确保一致性
- 调用基类 `OnActivateAsync`

### DeactivateOnIdle 资源回收
在 `GoOfflineAsync` 方法末尾调用 `DeactivateOnIdle()`，通知Orleans运行时此Grain处于空闲状态，可安全回收以释放资源。

## 战斗系统功能接口

### 攻击与技能
- `AttackAsync`: 处理普通攻击，返回伤害结果
- `CastSkillAsync`: 施放技能，包含技能ID、目标等参数
- `UseQingGongAsync` / `UseNeiGongAsync`: 使用轻功或内功技能
- `ComboAttackAsync`: 执行连击动作

### 装备管理
- `EquipItemAsync`: 装备物品到指定槽位
- `UnequipItemAsync`: 卸下指定槽位的装备
- `EnhanceEquipmentAsync`: 强化装备
- `RefineEquipmentAsync`: 精炼装备
- `InheritAttributesAsync`: 属性继承
- `WuXingCraftAsync`: 五行合成

### 技能系统
- `LearnSkillAsync`: 学习新技能
- `UpgradeSkillAsync`: 升级已有技能
- `QuerySkillCooldownAsync`: 查询技能冷却时间
- `QuerySkillProficiencyAsync`: 查询技能熟练度

### 社交与组织
- `JoinSectAsync`: 加入门派
- `HandleDuelAsync`: 发起比武切磋
- `HandleSwornBrotherAsync`: 结拜兄弟
- `HandleMasterApprenticeAsync`: 建立师徒关系
- `CreateTeamAsync` / `JoinTeamAsync`: 队伍管理
- `CreateGuildAsync` / `JoinGuildAsync`: 帮派管理

所有战斗相关方法均记录操作日志，返回标准化响应对象。

## 属性映射与验证规则

### IMapper 映射机制
系统使用 AutoMapper 实现 `CharacterEntity` 与 `CharacterInfo` 之间的双向映射。例如在创建角色时：

```csharp
var characterEntity = _mapper.Map<CharacterEntity>(request);
_characterState.State.CharacterInfo = _mapper.Map<CharacterInfo>(characterEntity);
```

### 敏感词过滤
在创建角色时对角色名应用过滤：

```csharp
request.CharacterName = request.CharacterName.FilterSensitiveWords(sensitiveWords: null);
```

该方法位于 `StringHelper` 工具类中，用于防止不当命名。

### 其他验证规则
- 用户状态检查：若账号被封禁（Status > 0）则禁止创建角色
- 名称唯一性校验：通过数据库查询确保无重复角色名
- 必填字段验证：如角色名不能为空

## 性能优化建议

### 避免频繁 WriteStateAsync
对于高频操作如角色移动，**绝不应在每次移动后调用 `WriteStateAsync`**。推荐做法：
- 仅在内存中更新位置
- 通过消息广播通知周围玩家
- 定期（如每分钟）或在区域切换、登出时批量持久化

### 合理使用缓存
利用 Orleans 内置状态管理减少数据库访问。对于不常变更的数据（如角色基础属性），可在激活时一次性加载至状态中。

### 异步非阻塞设计
所有方法均为 `async Task` 形式，确保Grain调用不会阻塞调度线程，提升整体吞吐量。

### 资源及时释放
通过 `DeactivateOnIdle()` 主动释放空闲Grain，避免内存泄漏，特别是在大规模在线场景下尤为重要。
