# 相机抖动与震荡优化设计方案

## 1. 问题诊断

### 1.1 核心问题描述

相机在特定场景下出现严重的抖动和震荡现象，可能导致用户眩晕感，影响游戏体验。根据现有实现和历史问题分析，主要表现为：

- **碰撞震荡**：相机在障碍物附近反复震荡，距离在不同值之间快速切换
- **视觉抖动**：相机位置或角度频繁微小变化，造成画面不稳定
- **穿透闪烁**：地面穿透防护与碰撞检测冲突，导致相机位置跳跃
- **多系统冲突**：碰撞检测、弹性跟随、FOV调整等多个系统同时作用造成反馈循环

### 1.2 问题分类与根因

| 问题类型 | 典型场景 | 根本原因 | 影响程度 |
|---------|---------|---------|---------|
| 碰撞边缘震荡 | 靠近墙体、障碍物 | 碰撞状态瞬间切换，速度参数不匹配 | 高 |
| 微小距离抖动 | 平滑移动时 | 缺乏防抖阈值，频繁插值计算 | 中 |
| 地面穿透跳跃 | 角色移动、地形变化 | 地面检测与碰撞调整时序冲突 | 高 |
| 多系统干扰 | 战斗、快速移动 | 碰撞、弹性、FOV同时修改无优先级 | 中 |
| 速度切换突变 | 碰撞恢复阶段 | 进入/退出碰撞时速度倍数差异过大 | 高 |

## 2. 优化策略设计

### 2.1 分层速度控制机制

#### 2.1.1 设计理念

采用基于距离变化幅度的分层速度策略，在稳定性与响应性之间取得平衡：

- **完全静止层**：微小变化时不响应，消除抖动源头
- **中速响应层**：中等变化平稳过渡，保持流畅性
- **快速响应层**：大幅变化快速调整，确保安全性
- **极速追赶层**：无碰撞恢复时加速回归，提升体验

#### 2.1.2 阈值与速度配置

| 距离变化范围 | 速度策略 | 速度倍数 | 应用场景 |
|------------|---------|---------|---------|
| < 10cm | 完全静止 | 0x | 微小抖动，直接忽略 |
| 10cm - 50cm | 中速响应 | 1.0x | 常规调整，平滑过渡 |
| 50cm - 200cm | 快速响应 | 2.5x | 碰撞避障，快速靠近 |
| > 200cm | 极速追赶 | 4.0x | 无碰撞恢复，快速回归理想距离 |

**基准速度参数**：
- CollisionSmoothSpeed：10.0（基准平滑速度）
- 实际应用速度 = 基准速度 × 对应倍数

#### 2.1.3 实现逻辑描述

计算当前距离与目标距离的差值，根据差值大小选择对应的速度策略：

```
输入：当前距离(currentDistance)、目标距离(targetDistance)、碰撞状态(hasCollision)
输出：平滑后的新距离

步骤：
1. 计算距离差值：distanceDiff = |currentDistance - targetDistance|
2. 根据distanceDiff和hasCollision选择速度倍数：
   - 若 distanceDiff < 10cm：返回currentDistance（不调整）
   - 若 distanceDiff < 50cm：speedMultiplier = 1.0
   - 若 hasCollision 且 distanceDiff >= 50cm：speedMultiplier = 2.5
   - 若 !hasCollision 且 distanceDiff > 200cm：speedMultiplier = 4.0
   - 其他情况：speedMultiplier = 1.5
3. 应用平滑插值：
   newDistance = Lerp(currentDistance, targetDistance, deltaTime × CollisionSmoothSpeed × speedMultiplier)
4. 返回newDistance
```

### 2.2 碰撞状态稳定机制

#### 2.2.1 问题描述

单帧碰撞检测波动导致碰撞状态频繁切换（True ↔ False），引发位置震荡。

#### 2.2.2 稳定延迟策略

引入状态稳定时间窗口，要求碰撞状态持续一定时间后才允许切换：

**配置参数**：
- CollisionStateStableTime：0.2秒（状态稳定时间）

**状态转换规则**：

| 当前状态 | 检测结果 | 持续时间 | 实际应用状态 |
|---------|---------|---------|------------|
| 无碰撞 | 检测到碰撞 | < 0.2s | 保持无碰撞 |
| 无碰撞 | 检测到碰撞 | ≥ 0.2s | 切换到碰撞 |
| 碰撞中 | 无碰撞 | < 0.2s | 保持碰撞 |
| 碰撞中 | 无碰撞 | ≥ 0.2s | 切换到无碰撞 |

#### 2.2.3 实现逻辑描述

```
状态变量：
- _wasColliding：上一帧的稳定碰撞状态
- _collisionStateChangeTime：状态变化首次检测时间
- _currentGameTime：当前游戏时间

逻辑流程：
1. 执行碰撞检测，获得原始结果：rawCollisionState
2. 若 rawCollisionState == _wasColliding：
   - 状态未变，重置 _collisionStateChangeTime = 0
   - 应用状态 = _wasColliding
3. 若 rawCollisionState != _wasColliding：
   - 状态变化，检查计时器：
     a) 若 _collisionStateChangeTime == 0：
        - 首次检测到变化，记录时间 _collisionStateChangeTime = _currentGameTime
        - 应用状态 = _wasColliding（保持原状态）
     b) 若 _collisionStateChangeTime > 0：
        - 计算持续时间：duration = _currentGameTime - _collisionStateChangeTime
        - 若 duration < 0.2s：
          - 未达到稳定时间，应用状态 = _wasColliding
        - 若 duration >= 0.2s：
          - 达到稳定时间，允许切换，应用状态 = rawCollisionState
          - 更新 _wasColliding = rawCollisionState
          - 重置 _collisionStateChangeTime = 0
4. 使用稳定后的状态进行后续距离调整
```

### 2.3 动态内部碰撞阈值

#### 2.3.1 问题背景

固定的内部碰撞阈值（如100cm）在相机被压缩到最小距离时会误判，导致忽略真实碰撞。

#### 2.3.2 动态阈值计算

内部碰撞阈值应基于当前相机实际距离动态调整：

**计算公式**：
```
动态内部碰撞阈值 = Min(当前相机距离 × 0.3, 100cm)
```

**示例**：
- 当前距离 = 1500cm：阈值 = Min(450cm, 100cm) = 100cm
- 当前距离 = 200cm：阈值 = Min(60cm, 100cm) = 60cm
- 当前距离 = 150cm：阈值 = Min(45cm, 100cm) = 45cm

#### 2.3.3 碰撞忽略逻辑

在多射线碰撞检测中，对每条射线的碰撞结果应用动态阈值过滤：

```
对于每条射线的碰撞结果：
1. 获取碰撞距离：hitDistance
2. 计算动态阈值：threshold = Min(currentCameraDistance × 0.3, 100)
3. 若 hitDistance < threshold：
   - 判定为内部碰撞，忽略此结果
   - 记录日志：检测到内部碰撞 {objectName} @ {hitDistance}cm
4. 若 hitDistance >= threshold：
   - 有效碰撞，参与安全距离计算
```

### 2.4 地面穿透防护优化

#### 2.4.1 三重防护机制

| 机制 | 作用 | 参数 |
|-----|------|-----|
| 防抖阈值 | 避免微小高度变化触发调整 | 20cm |
| 平滑插值 | 平滑过渡到目标高度 | Lerp速度 5.0 |
| 状态缓存 | 记录上次地面高度，避免重复计算 | _lastGroundHeight |

#### 2.4.2 执行时序要求

地面检测必须在碰撞检测和位置设置之间执行：

```
执行顺序：
1. 计算理想相机位置（基于Distance和Pitch/Yaw）
2. 执行碰撞检测，调整为碰撞安全位置
3. 【此处插入】执行地面穿透检测：
   - 从相机位置向下发射射线
   - 检测到地面且相机低于地面 + MinDistanceFromGround时
   - 计算目标高度：groundHeight + MinDistanceFromGround
   - 若 |目标高度 - _lastGroundHeight| > 20cm（防抖阈值）：
     * 平滑插值：newY = Lerp(currentY, targetY, deltaTime × 5.0)
     * 更新相机Y坐标
     * 缓存 _lastGroundHeight = 目标高度
4. 设置相机最终位置
5. 设置相机朝向（LookAt）
```

### 2.5 多系统优先级控制

#### 2.5.1 系统优先级定义

| 优先级 | 系统模块 | 触发条件 | 禁用目标 |
|-------|---------|---------|---------|
| P0（最高） | 地面穿透防护 | 相机低于地面阈值 | 无 |
| P1 | 碰撞检测 | 检测到障碍物 | 弹性跟随、FOV调整 |
| P2 | 弹性跟随 | 目标移动 | FOV调整（战斗时） |
| P3 | 动态FOV | 速度变化 | 无 |
| P4 | 相机抖动 | 外部触发 | 无（叠加应用） |

#### 2.5.2 冲突避免策略

在每帧更新中按优先级顺序执行，高优先级系统激活时禁用低优先级：

```
每帧更新逻辑：
1. 检测地面穿透（P0）：
   - 若检测到穿透风险：执行地面防护，跳过后续步骤
2. 检测碰撞（P1）：
   - 若 hasCollision == true：
     * 禁用弹性跟随（设置弹性系数为0）
     * 禁用FOV调整（锁定当前FOV）
     * 执行碰撞距离调整
3. 若无碰撞，检测弹性跟随（P2）：
   - 若目标速度 > 阈值：
     * 在战斗状态时禁用FOV调整
     * 执行弹性跟随计算
4. 若允许，执行动态FOV（P3）：
   - 根据速度调整FOV
5. 应用相机抖动（P4）：
   - 始终叠加应用，不受其他系统影响
```

### 2.6 平滑插值优化

#### 2.6.1 防止过度平滑

**问题**：平滑速度过慢导致相机延迟和定位不准。

**诊断方法**：
- 调试阶段临时禁用平滑（直接赋值目标位置）
- 若问题消失，确认为插值速度问题

**优化参数**：
- PositionSmoothing：10.0（位置平滑速度）
- RotationSmoothing：5.0（旋转平滑速度）
- 战斗模式下提升至 15.0 和 8.0，增强响应性

#### 2.6.2 旋转一致性保障

**问题**：直接使用原始Yaw进行位置计算，与平滑后的旋转不一致，产生重影。

**解决方案**：
- 引入 _smoothYaw 和 _smoothPitch 变量
- 位置计算和视角设置都使用平滑后的角度值

```
每帧更新：
1. 获取输入调整原始Yaw/Pitch
2. 平滑插值：
   _smoothYaw = Lerp(_smoothYaw, Yaw, deltaTime × RotationSmoothing)
   _smoothPitch = Lerp(_smoothPitch, Pitch, deltaTime × RotationSmoothing)
3. 位置计算使用 _smoothYaw 和 _smoothPitch
4. 相机旋转也使用 _smoothYaw 和 _smoothPitch
```

## 3. 配置参数建议

### 3.1 核心参数表

| 参数名称 | 建议值 | 单位 | 说明 |
|---------|-------|------|------|
| CollisionSmoothSpeed | 10.0 | 无量纲 | 碰撞平滑基准速度 |
| PositionSmoothing | 10.0 | 无量纲 | 位置平滑速度 |
| RotationSmoothing | 5.0 | 无量纲 | 旋转平滑速度 |
| CollisionStateStableTime | 0.2 | 秒 | 碰撞状态稳定时间 |
| MinDistanceFromGround | 50.0 | cm | 最小离地高度 |
| GroundCheckInterval | 0.1 | 秒 | 地面检测间隔 |
| MinDistanceChangeThreshold | 10.0 | cm | 最小距离变化阈值（防抖） |
| MediumDistanceChangeThreshold | 50.0 | cm | 中等距离变化阈值 |
| LargeDistanceChangeThreshold | 200.0 | cm | 大距离变化阈值 |
| CollisionOffset | 20.0 | cm | 碰撞安全偏移 |
| InnerCollisionRatioLimit | 0.3 | 无量纲 | 内部碰撞动态比例 |
| InnerCollisionMaxThreshold | 100.0 | cm | 内部碰撞最大阈值 |

### 3.2 场景化配置推荐

#### 室外开阔场景
- CollisionSmoothSpeed：8.0（降低，减少不必要计算）
- PositionSmoothing：12.0（提升响应性）
- 禁用地面检测频率，降低为0.2秒间隔

#### 室内狭窄场景
- CollisionSmoothSpeed：15.0（提升碰撞响应）
- CollisionStateStableTime：0.15秒（缩短稳定时间）
- 启用高精度碰撞检测（9射线）

#### 战斗场景
- PositionSmoothing：15.0（快速响应）
- RotationSmoothing：8.0（快速转向）
- 禁用弹性跟随，禁用动态FOV

## 4. 实施步骤建议

### 4.1 第一阶段：核心防抖优化（高优先级）

**目标**：消除最明显的抖动和震荡

1. **实施分层速度控制**
   - 在ThirdPersonCamera的碰撞距离调整逻辑中应用分层速度
   - 在CameraSystem的平滑插值中应用防抖阈值
   - 验证：在障碍物边缘测试，观察是否消除震荡

2. **实施碰撞状态稳定机制**
   - 添加状态稳定时间窗口
   - 添加诊断日志，记录状态切换过程
   - 验证：观察日志，确认状态切换频率降低

3. **实施动态内部碰撞阈值**
   - 修改多射线碰撞检测中的阈值判断
   - 验证：在相机被压缩时不会误判无碰撞

**预期效果**：
- 碰撞边缘震荡消失
- 相机距离变化平滑连续
- 无误判导致的位置跳跃

### 4.2 第二阶段：地面防护与插值优化（中优先级）

**目标**：解决地面穿透和平滑延迟问题

1. **优化地面穿透防护**
   - 调整执行时序，放在碰撞检测之后
   - 添加防抖阈值（20cm）
   - 实施平滑插值而非直接赋值
   - 验证：在起伏地形快速移动，观察是否穿透

2. **优化平滑插值参数**
   - 调整PositionSmoothing和RotationSmoothing到建议值
   - 实施旋转一致性（_smoothYaw/_smoothPitch）
   - 验证：观察是否有重影或延迟感

**预期效果**：
- 不再穿透地面
- 相机跟随流畅无重影
- 响应速度适中

### 4.3 第三阶段：多系统协调（低优先级）

**目标**：消除多系统冲突导致的反馈循环

1. **实施优先级控制**
   - 按P0-P4顺序重构更新逻辑
   - 碰撞时禁用弹性和FOV
   - 添加系统激活状态日志
   - 验证：在战斗场景观察是否有异常抖动

2. **性能优化**
   - 根据场景类型动态调整检测频率
   - 启用碰撞缓存机制
   - 监控缓存命中率

**预期效果**：
- 无多系统冲突
- 各场景下表现稳定
- 性能开销合理

## 6. 风险与备选方案

### 6.1 潜在风险

| 风险项 | 影响程度 | 缓解措施 |
|-------|---------|---------|
| 分层速度阈值不合适 | 中 | 提供可配置参数，运行时调整 |
| 状态稳定时间过长 | 中 | 缩短至0.15秒，增加响应性 |
| 地面检测性能开销 | 低 | 增加检测间隔至0.2秒 |
| 多系统禁用影响体验 | 中 | 仅在明确冲突时禁用，非全局 |

### 6.2 备选方案

若分层速度策略效果不佳，可采用：
- **指数衰减模型**：距离越近衰减越快
- **预测性调整**：根据目标速度预测碰撞，提前调整
- **自适应阈值**：根据帧率和场景复杂度动态调整阈值
