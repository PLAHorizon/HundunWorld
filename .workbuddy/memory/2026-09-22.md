### 结论：模型路径本身没错，错的是资产 GUID 引用与导入参数

| 项目 | 结论 | 证据 |
| --- | --- | --- |
| 身体模型路径 | **正确** | `Content/Character/Models/skm_uefn_mannequin.flax` 存在（264,831 B） |
| 身体模型 GUID | **正确** | 解析 `.flax` 头部 offset 28 得 `bb21309c62654de9a63cdf826ed3116e`，与 `EquipmentDatabase.DefaultBodyModelGuid` / `HundunWorldGame.SkinnedModelGuid` 一致（日志亦确认按 SkinnedModel 加载成功） |
| AnimationGraph GUID | **错误** | 源码两处写死 `ceded67f4bb2623f40b4dcb493b0d419`；资产 `Animation Graph.flax` 真实 ID = `ceded67f623f4bb2b4dcb44019d4b093`（写死值字节顺序被写乱） |
| `CharacterRoot-1.prefab` | **错误** | 引用失效的 `SkinnedModel=c7c70820409088e4d96db396a43c410f` 与错误 AnimationGraph GUID（该 prefab 目前无人引用） |
| 模型导入参数 | **被破坏** | `skm_uefn_mannequin.flax` 内嵌导入设置：`Type=1` ✓、**`Scale=0.0001`**（历史正确资产为 `1.0`）、**`Rotation=(0,0,0,0)`**（非法退化四元数；历史为 `(0,0,0,1)`）。表现为运行时 `自动取景完成：身高=0.03`（正确应约 300 单位） |

根因：`AutoSkinnedModelImportPlugin` 用 `new ModelTool.Options { ... }` 构造导入设置 → Scale/Rotation 等字段无初值 → 重建导入写出脏参数。
正确写法（Flax 1.12 已确认 API 存在）：以 `ModelTool.Options.Default` 为基准 + `FlaxEditor.Editor.TryRestoreImportOptions(ref options, assetPath)` 读回原设置，只改需要改的字段。

## 追加：角色选择界面「看不到角色模型」= 同一个导入缩放回归

用户反馈截图（21:46，场景已是蓝天）：角色选择界面右侧只有天空，没有模型。

### 根因链（已确认）

1. `Content/Maps/Character.scene` 由 `GameSceneManager` 以 GUID `f1a2b3c4f708d5e64c3b2a19807f6e5d` 加载（运行时场景名 = `Scene`）。
2. 角色选择界面的 3D 区域 = `Game/UI/Components/CharacterPreviewPanel.cs`，
   `ActorsSource = ActorsSources.Scenes`（**渲染整个场景**，所以场景 Sky 本来就会出现在这里，不是新引入的），
   相机来自 `UICharacterCameraSystem`：`_modelScale = 1.0`、相机距离约 250、`LookAt(0, 90, 0)`、near/far 1/1000
   —— **完全按「约 180 单位(cm) 身高」硬编码取景**。
3. 而 18:47 那次自动重建导入把资产缩放写成了 `Scale=0.0001` → 模型实际约 **0.03 单位**，
   在 250 单位外是一个亚像素点 ⇒ **角色选择界面看不到角色**（Ink 的 `CharacterPreview3D` 因为有自动取景，
   反而"看起来正常"，掩盖了这个回归）。
4. 物理尺寸异常也会连带影响阴影/雾等世界空间效果。

### 本轮改动

- `Source/Game/UI/Components/UICharacterCameraSystem.cs`
  - 新增 `VerifyCharacterScale(Asset, string)`：读取模型 `GetBox(0)`，最大边不在 20~5000 单位区间时
    用 `Debug.LogError` 明确报出「相机将看不到角色」+ 修复动作；正常时打印实测尺寸（供后续标定）。
  - 注意：**`FlaxEngine.SkinnedModel` 与 `FlaxEngine.Model` 没有继承关系**（都不派生自对方），
    统一按 `Asset` 入参再分别 `is` 判断，否则 CS8121/CS1503。
- `Source/Game/Editor/AutoSkinnedModelImportPlugin.cs`
  - 判据改为以「模型包围盒最大边」为主（读回导入设置可能失败并退化成默认值 → 会漏修），
    阈值 `MinSaneModelSize=1`；修复时显式把 `Scale` 置为 `CorrectImportScale=1.0`、`Rotation=Identity`。
  - ContentDatabase 查不到资产项时新增回退：`FlaxEditor.Editor.Import(源FBX绝对路径, AssetPath, options)`
    （`Globals.ProjectFolder` 拼路径；返回 true 表示**失败**）。源路径写常量
    `SourceAssets/Character/Models/skm_uefn_mannequin.FBX` —— **`ModelTool.Options` 里没有 ImportPath 字段**，
    它只存在于资产内嵌的导入设置 JSON 中。
- 编译：`dotnet build Game.csproj` → **0 错误**，DLL 22:00:35 更新，新符号已确认在 DLL 中。

### 坏消息：这次重建导入**换了资产 GUID**

- 旧 `bb21309c-6265-4de9-a63c-df826ed3116e` → 新 **`b0823a85-76cb-47cb-9932-f5af61aa1ef7`**
  （`.flax` 头部 **offset 28** 起 16 字节实测；用 `.backup` 交叉验证解析正确）
- 原因：ContentDatabase 双查失败时走的是我加的**回退分支 `FlaxEditor.Editor.Import(...)`**，
  该 API 会**新建资产 = 新 GUID**（而 `ContentImporting.Reimport` 才保留 ID）。
  ⇒ 所有按 GUID 的引用失效；编辑器会话内的内容注册与磁盘不一致 → 路径加载也报 `Missing file`。
- **教训：不要用 `Editor.Import` 修复已有资产；路径是稳定标识，GUID 不是。**
